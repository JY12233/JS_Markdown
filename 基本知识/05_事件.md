# 冒泡

在 JavaScript 中，事件绑定是前端开发的核心。根据事件传播机制的不同，事件主要分为**冒泡事件**和**非冒泡事件**两大类。

没问题，按照您的要求，我将事件体系重新进行了结构化梳理，把大类拆分为了独立的标题，并严格按照是否冒泡进行了分类。以下是完整的 JavaScript 事件列表：

## 冒泡事件

这类事件在触发后，会沿着 DOM 树向上传播，非常适合用于**事件委托**。

### 鼠标事件

| 事件名称      | 触发时刻                             |
| ------------- | ------------------------------------ |
| `click`       | 元素被点击（按下并释放）时触发       |
| `dblclick`    | 元素被双击时触发                     |
| `mousedown`   | 鼠标按钮在元素上按下时触发           |
| `mouseup`     | 鼠标按钮在元素上释放时触发           |
| `mousemove`   | 鼠标在元素内移动时持续触发           |
| `mouseover`   | 鼠标进入元素或其子元素时触发         |
| `mouseout`    | 鼠标离开元素或其子元素时触发         |
| `contextmenu` | 右键点击打开上下文菜单时触发         |
| `wheel`       | 鼠标滚轮滚动时触发                   |
| `focusin`     | 元素（或其子元素）即将获得焦点时触发 |
| `focusout`    | 元素（或其子元素）即将失去焦点时触发 |

### 触摸事件

| 事件名称      | 触发时刻                                 |
| ------------- | ---------------------------------------- |
| `touchstart`  | 手指首次接触屏幕时触发                   |
| `touchmove`   | 手指在屏幕上滑动时持续触发               |
| `touchend`    | 手指从屏幕离开时触发                     |
| `touchcancel` | 触摸被意外中断时触发（如来电、系统弹窗） |

### 拖拽事件

| 事件名称    | 触发时刻                             |
| ----------- | ------------------------------------ |
| `dragstart` | 开始拖拽元素时触发                   |
| `drag`      | 元素正在被拖拽时持续触发             |
| `dragend`   | 拖拽操作结束时触发                   |
| `dragenter` | 拖拽的元素进入有效放置目标时触发     |
| `dragover`  | 拖拽的元素在有效放置目标内移动时触发 |
| `dragleave` | 拖拽的元素离开有效放置目标时触发     |
| `drop`      | 元素被放置到目标区域时触发           |

### 剪贴板事件

| 事件名称 | 触发时刻           |
| -------- | ------------------ |
| `copy`   | 用户复制内容时触发 |
| `cut`    | 用户剪切内容时触发 |
| `paste`  | 用户粘贴内容时触发 |

### 动画与过渡事件

| 事件名称             | 触发时刻                   |
| -------------------- | -------------------------- |
| `animationstart`     | CSS 动画开始时触发         |
| `animationend`       | CSS 动画结束时触发         |
| `animationiteration` | CSS 动画每次重复播放时触发 |
| `transitionend`      | CSS 过渡效果完成时触发     |

### 键盘事件

| 事件名称  | 触发时刻                                                     |
| --------- | ------------------------------------------------------------ |
| `keydown` | 用户按下任意键（包括功能键）时触发，如果按键被持续按住，则会重复触发。 |
| `keyup`   | 用户释放按键时触发。                                         |

### 表单验证事件

| 事件名称  | 触发时刻                                                     |
| --------- | ------------------------------------------------------------ |
| `invalid` | 当表单元素的值未能通过其约束条件（如 `required`、`pattern` 等）的校验时触发。 |
| `change`  | 当 `<input>`、`<select>`、`<textarea>` 等元素的值发生改变并**失去焦点**时触发。 |
| `input`   | 当 `<input>`、`<textarea>` 等元素的值发生改变时立即触发。    |

## 非冒泡事件

这类事件在触发后不会向父节点传递，通常用于处理特定的状态变化或全局行为。

### 鼠标与焦点事件

| 事件名称     | 触发时刻                                       |
| ------------ | ---------------------------------------------- |
| `mouseenter` | 鼠标进入元素边界时触发（不冒泡，不进入子元素） |
| `mouseleave` | 鼠标完全离开元素边界时触发（不冒泡）           |
| `focus`      | 元素获得焦点时触发                             |
| `blur`       | 元素失去焦点时触发                             |

### 表单事件

| 事件名称 | 触发时刻                                 |
| -------- | ---------------------------------------- |
| `submit` | 表单提交时触发（仅作用于 `<form>` 元素） |
| `reset`  | 表单被重置时触发                         |

### 媒体事件

| 事件名称       | 触发时刻                        |
| -------------- | ------------------------------- |
| `play`         | 媒体（音频/视频）开始播放时触发 |
| `pause`        | 媒体暂停播放时触发              |
| `ended`        | 媒体播放结束时触发              |
| `timeupdate`   | 媒体播放进度（时间）更新时触发  |
| `volumechange` | 媒体音量发生变化时触发          |

### 窗口与文档事件

| 事件名称           | 触发时刻                                                  |
| ------------------ | --------------------------------------------------------- |
| `load`             | 页面或资源（如图片、脚本）完全加载完毕后触发              |
| `DOMContentLoaded` | HTML 文档完全加载和解析完毕（不等待样式表、图片等）时触发 |
| `resize`           | 浏览器窗口大小发生改变时触发                              |
| `scroll`           | 元素或窗口发生滚动时触发                                  |
| `beforeunload`     | 页面即将卸载前触发（常用于弹出提示，防止用户意外离开）    |
| `unload`           | 页面完全卸载时触发                                        |
| `visibilitychange` | 页面可见性发生变化时触发（如切换浏览器 Tab、最小化窗口）  |
| `hashchange`       | URL 的哈希值（`#` 后面的部分）发生变化时触发              |
| `popstate`         | 浏览器历史记录发生变化时触发（如点击前进/后退按钮）       |

### 移动端设备事件

| 事件名称            | 触发时刻                                               |
| ------------------- | ------------------------------------------------------ |
| `devicemotion`      | 检测到设备加速度和旋转速率变化时触发                   |
| `deviceorientation` | 检测到设备物理方向变化时触发（多用于指南针或屏幕旋转） |

### 键盘事件

| 事件名称   | 触发时刻                                                     |
| ---------- | ------------------------------------------------------------ |
| `keypress` | 用户按下并释放一个能产生字符值的键时触发（已废弃，不推荐使用）。 |

# 事件绑定

`addEventListener` 是浏览器原生提供的用于向指定元素添加事件监听器的方法。在使用时，需传入事件类型、回调函数以及可选的配置参数，它主要用于为 DOM 元素绑定交互行为（如点击、输入、鼠标移动等）。

鉴于前两个参数（事件类型与回调函数）已非常熟悉，以下将重点介绍其第三个参数 `options` 的高级配置。

## 使用格式

```javascript
element.addEventListener(
  type, // 事件类型：字符串类型，如 'click'、'keydown'（此处略过）
  listener, // 回调函数：事件触发时执行的函数（此处略过）
  options // 配置对象：包含 capture、once、passive、signal 等高级选项的布尔值或对象
);
```

## options 参数

| 参数名称  | 作用描述                                                     | 可选值或数据类型            |
| --------- | ------------------------------------------------------------ | --------------------------- |
| `capture` | 控制事件监听器是否在捕获阶段触发。<br />若为 `true`，则在事件向下传播（捕获）时触发；<br />若为 `false`（默认），则在事件向上冒泡时触发。 | `true` 或 `false`（布尔值） |
| `once`    | 控制事件监听器是否只执行一次。<br />若为 `true`，监听器在首次触发后会自动移除，<br />无需手动调用 `removeEventListener`。 | `true` 或 `false`（布尔值） |
| `passive` | 告诉浏览器该监听器永远不会调用 `preventDefault()`。<br />若为 `true`，浏览器可立即滚动页面而无需等待 JavaScript 执行完毕，<br />极大提升滚动性能（常用于 `touchmove`、`wheel` 事件）。 | `true` 或 `false`（布尔值） |
| `signal`  | 接收一个 `AbortSignal` 对象。<br />当该信号被中止（调用 `abort()`）时，对应的事件监听器会被自动移除，<br />非常适合组件销毁时的资源清理。 | `AbortSignal` 对象          |

## 代码示例

以下示例展示了如何使用 `options` 对象中的 `once` 和 `passive` 属性。

```javascript
const button = document.querySelector('#myButton');

// 示例 1：使用 once 属性，按钮点击一次后自动解绑
button.addEventListener('click', () => {
  console.log('这个点击事件只会触发一次');
}, { once: true });

// 示例 2：使用 passive 属性，优化移动端滚动性能
window.addEventListener('touchmove', (event) => {
  // 即使这里不调用 preventDefault()，浏览器也能流畅滚动
  console.log('页面正在滚动');
}, { passive: true });
```

# submit 事件

## 定义

`submit` 事件是 HTML 表单（`<form>`）在提交时触发的原生 DOM 事件。该事件的核心作用是在表单数据发送至服务器之前，提供一个拦截与自定义处理的钩子。通过监听此事件，开发者可以执行表单验证、数据预处理、阻止页面默认刷新，以及实现 AJAX 异步提交等高级交互逻辑。

## 核心特性

1. 触发时机

   当用户点击表单内的提交按钮（`<button type="submit">` 或 `<input type="submit">`），或在表单内的输入框中按下回车键（Enter）时触发。

2. 事件绑定对象

   `submit` 事件只能绑定在 `<form>` 元素本身，不能直接绑定在提交按钮上。

3. 与 `form.submit()` 的区别

   通过 JavaScript 直接调用 `form.submit()` 方法提交表单时，**不会**触发 `submit` 事件。只有用户交互或调用 `form.requestSubmit()` 方法时才会触发。

4. 与表单验证的联动

   如果表单未通过 HTML5 原生验证（如 `required` 属性校验失败），浏览器会触发 `invalid` 事件并阻止提交，此时 `submit` 事件不会被触发。

## 使用方法

使用 `submit` 事件的标准流程包含三个步骤：获取表单元素、监听 `submit` 事件、在回调函数中阻止默认行为并进行自定义处理。

**基础语法格式**

```javascript
// 获取表单元素
const form = document.querySelector('form');

// 监听 submit 事件
form.addEventListener('submit', function(event) {
    // 核心操作：阻止表单默认的页面刷新与跳转行为
    event.preventDefault(); 

    // 在此处执行自定义逻辑，如数据验证或 AJAX 提交
    console.log('表单已拦截，正在执行自定义提交逻辑');
});
```

## 关键参数与属性详解

| 属性/方法名称            | 作用描述                                                     | 可选值或数据类型           |
| ------------------------ | ------------------------------------------------------------ | -------------------------- |
| `event.preventDefault()` | 阻止表单的默认提交行为（即阻止页面刷新或跳转）               | 方法（无返回值）           |
| `event.submitter`        | 返回触发本次提交动作的具体按钮元素<br />（`SubmitEvent` 特有属性） | `HTMLElement` 对象（只读） |
| `event.target`           | 返回触发事件的表单元素本身                                   | `HTMLFormElement` 对象     |

## 常见应用场景

1. 前端表单验证

   在数据发送前检查输入格式（如邮箱、手机号），若不符合要求则阻止提交并给出提示。

2. AJAX 异步提交

   结合 `fetch` 或 `axios`，在 `submit` 事件中拦截默认行为，将数据以 JSON 或 `FormData` 格式异步发送至服务器，实现无刷新体验。

3. 数据预处理

   在提交前对表单数据进行清洗，例如去除首尾空格（`trim()`）、密码加密或补充隐藏字段（如时间戳）。

4. 多按钮提交区分

   利用 `event.submitter` 属性，可以判断用户点击的是“保存草稿”按钮还是“正式发布”按钮，从而执行不同的提交逻辑。

## 常见误区

1. 忘记 `preventDefault()`

   若未在回调函数开头调用 `event.preventDefault()`，表单会立即提交并刷新页面，后续的 JavaScript 逻辑将无法执行。

2. 事件绑定位置错误

   将 `submit` 事件绑定在 `<button>` 或 `<input type="submit">` 上是无效的，必须绑定在 `<form>` 上。

3. DOM 未加载完成

   若脚本在 HTML 解析前执行，可能无法获取到表单元素。建议将代码包裹在 `DOMContentLoaded` 事件中，或置于 `<body>` 底部。
