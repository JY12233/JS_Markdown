# 脚本编译

## 背景与需求

在学习 Ajax 的过程中，需要使用 `axios` 库发送 HTTP 请求。TypeScript 可以提供代码提示和类型检查，因此选择在 TypeScript 中编写代码。

期望的工作流程为：编写 TypeScript 源码 -> 编译为 JavaScript -> 在 HTML 中通过 `<script>` 标签引入编译后的文件并运行。

HTML 中通过 `<script>` 标签加载 `axios` 的 CDN 文件，同时希望编译后的 JavaScript 能够被浏览器正常加载，且保留完整的类型提示。

## 核心问题

TypeScript 中使用 `import axios from "axios"` 导入第三方库时，编译后的 JavaScript 会保留该 `import` 语句。浏览器加载普通脚本时遇到 `import` 关键字会抛出语法错误，且浏览器无法解析裸模块标识符 `"axios"`。

即使使用 `import type` 仅导入类型，编译后的文件中仍可能出现 `export {}`，导致普通 `<script>` 标签加载时报 `Unexpected token 'export'` 错误。

## 解决方案

最终采用的方式为：在 HTML 中使用 `<script type="module">` 加载编译后的 JavaScript 文件，同时在 TypeScript 源码中使用 `import type` 导入类型，并通过 `declare const` 声明全局 `axios` 变量，由 HTML 中通过普通 `<script>` 加载的 `axios` CDN 提供运行时实现。

### 核心思路

1. 利用 `<script type="module">` 允许 `import` 和 `export` 语法的特性，使编译后可能残留的 `export {}` 不再报错。
2. 在 TypeScript 中使用 `import type` 仅导入类型，不产生运行时导入代码。
3. 通过 `declare const axios: import('axios').AxiosStatic` 声明全局 `axios` 变量的类型，获得编辑器提示。
4. 运行时 `axios` 由 HTML 中通过 CDN 加载的 UMD 版本提供。

### 具体实施步骤

#### 安装类型声明

```bash
npm install -D typescript @types/axios
```

#### 编写源码

```typescript
// 仅导入类型，编译后完全擦除
import type { AxiosStatic } from 'axios';

// 声明全局 axios 变量，类型为 AxiosStatic
declare const axios: AxiosStatic;

axios
    .get("https://hmajax.itheima.net/api/province")
    .then((result) => {
        const list: string[] = result.data.list;
        console.log(list);
        document.write(list.join("<br>"));
    });
```

#### 配置 `tsconfig.json`

```json
{
  "compilerOptions": {
    "target": "ES6",
    "module": "ESNext",
    "outDir": "./dist",
    "strict": true
  }
}
```

#### 编译

```bash
tsc
```

编译后的 JavaScript 文件（例如 `dist/01_请求示例.js`）可能包含 `export {};`，但不会包含实际的 `import` 语句（因为 `import type` 被擦除）。

#### 引用

```html
<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
</head>
<body>
    <!-- 加载 axios 的 UMD 版本，使其成为全局变量 -->
    <script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
    <!-- 使用 type="module" 加载编译后的脚本 -->
    <script type="module" src="dist/01_请求示例.js"></script>
</body>
</html>
```

## 原理解释

### `type="module"`

1. 浏览器中，`<script type="module">` 脚本被视为 ES Module，完全支持 `import` 和 `export` 语法。
2. 编译后残留的 `export {}` 在模块脚本中是合法的空导出语句，不会触发语法错误。

### `import type`

1. `import type` 是 TypeScript 的纯类型导入语法，编译后会被完全擦除，不产生任何 JavaScript 代码。
2. 因此编译后的文件中不会包含 `import axios from "axios"` 这样的运行时导入语句，避免了浏览器无法解析裸模块标识符的问题。

### 类型提示的来源

1. `import type { AxiosStatic } from 'axios'` 从 `@types/axios` 包中获取类型信息。
2. `declare const axios: AxiosStatic` 告诉 TypeScript 在全局环境中存在一个名为 `axios` 的变量，其类型为 `AxiosStatic`。
3. VSCode 通过 TypeScript 语言服务读取这些类型定义，提供完整的代码补全、方法签名提示和类型检查。

### 运行时 `axios` 的来源

1. HTML 中通过普通 `<script>` 加载 `axios.min.js`，该文件会将 `axios` 挂载到全局对象 `window` 上。
2. 模块脚本中可以访问全局变量 `axios`，因此 `axios.get` 等调用在运行时能够正常执行。

## 总结

该方案成功实现了在 TypeScript 中获得类型提示、编译后生成可被浏览器模块脚本加载的 JavaScript 文件，且无需引入打包工具或 `importmap`。其关键点在于：

1. 使用 `type="module"` 允许模块语法，避免 `export` 报错。
2. 使用 `import type` 仅导入类型，避免运行时导入裸模块。
3. 通过 CDN 加载库的 UMD 版本，将库暴露为全局变量，供模块脚本使用。

此方案适用于学习阶段和小型项目，兼顾了类型安全与部署便捷性。
