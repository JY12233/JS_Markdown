# class 介绍

## 语法格式

`class` 关键字用于定义面向对象编程中的类，作为创建对象的蓝图或模板。

```typescript
class User {
    // 属性必须要先声明
    public name: string; // 声明公有属性，外部可自由访问
    private age: number; // 声明私有属性，仅类内部可访问
    protected id: number; // 声明受保护属性，类内部及子类可访问

    constructor(name: string, age: number, id: number) { // 构造函数，在实例化时自动执行
    this.name = name; // 初始化公有属性
    this.age = age; // 初始化私有属性
    this.id = id; // 初始化受保护属性
    }

    public greet(): string { // 声明公有方法，外部可调用
    return `Hello, ${this.name}`; // 返回问候语
    }

    private getAge(): number { // 声明私有方法，仅内部可调用
    return this.age; // 返回私有属性值
    }
}
```

属性也可以简写。

```ts
class User {
    constructor(public name: string, protected age: number, private id: number) { }
}
```



## 语法成分详解

| 语法成分      | 作用描述                                                     | 数据类型要求                         | 可选写法                 |
| ------------- | ------------------------------------------------------------ | ------------------------------------ | ------------------------ |
| `class`       | 声明类的关键字                                               | 无                                   | 无                       |
| `ClassName`   | 自定义的类名称                                               | 必须遵循标识符命名规范（大驼峰命名） | 无                       |
| `constructor` | 类的构造函数，用于初始化实例属性                             | 无                                   | 若无需初始化逻辑，可省略 |
| `public`      | 访问修饰符，表示公有成员                                     | 无                                   | 默认修饰符，可省略       |
| `private`     | 访问修饰符，表示私有成员                                     | 无                                   | 无                       |
| `protected`   | 访问修饰符，表示受保护成员                                   | 无                                   | 无                       |
| `readonly`    | 只读修饰符，表示属性初始化后不可修改<br />类似 java 中的 `final` | 无                                   | 可与访问修饰符组合使用   |
| `static`      | 静态修饰符，表示属于类本身而非实例的成员                     | 无                                   | 无                       |
| `abstract`    | 抽象修饰符，表示类或成员必须被子类实现                       | 无                                   | 仅用于抽象类或抽象成员   |

> 默认访问修饰符为 `public`。
>
> 抽象类可以有抽象方法，也可以有具体实现。抽象方法不能写 `{}`。

## 常见配套语法

| 配套语法     | 行为影响                                         |
| ------------ | ------------------------------------------------ |
| `extends`    | 实现类的继承，子类可继承父类的非私有成员         |
| `implements` | 强制类实现指定接口定义的所有属性和方法           |
| `super()`    | 在子类构造函数中调用父类构造函数，完成父类初始化 |
| `override`   | 显式标记子类方法覆盖了父类同名方法（TS 4.3+）    |

## 代码示例

`class` 关键字常与 `extends`、`implements` 配合使用，构建完整的面向对象体系：

```typescript
// 定义接口约束类结构
interface Printable {
  print(): void;
}

// 定义抽象基类
abstract class BaseEntity {
    protected id: number;

    constructor(id: number) {
    this.id = id;
    }

	// 抽象方法没有函数体
    abstract getInfo(): string; // 抽象方法，子类必须实现
}

// 子类继承并实现接口
class User extends BaseEntity implements Printable {
    public name: string;

    constructor(id: number, name: string) {
    super(id); // 调用父类构造函数
    this.name = name;
    }

    getInfo(): string { // 实现抽象方法
    return `User: ${this.name}, ID: ${this.id}`;
    }

    print(): void { // 实现接口方法
    console.log(this.getInfo());
    }
}
```

# 类存取器

## 语法格式

`get` 和 `set` 关键字用于在类中定义存取器（Accessors），允许以属性访问的方式间接获取或设置类的内部状态，同时附加自定义逻辑。

```typescript
class Person {
  private _name: string; // 声明私有属性，存储实际数据

  constructor(name: string) {
    this._name = name; // 在构造函数中初始化私有属性
  }

  get name(): string { // 定义 getter，用于获取属性值
    return this._name; // 返回私有属性的值
  }

  set name(value: string) { // 定义 setter，用于设置属性值
    if (value.length < 2) { // 在 setter 中添加数据验证逻辑
      throw new Error("Name must be at least 2 characters"); // 验证失败时抛出异常
    }
    this._name = value; // 验证通过后，更新私有属性的值
  }
}
```

## 语法成分详解

| 语法成分             | 作用描述                     | 数据类型要求                 | 可选写法                         |
| -------------------- | ---------------------------- | ---------------------------- | -------------------------------- |
| `get`                | 声明取值器（Getter）的关键字 | 无                           | 无                               |
| `set`                | 声明存值器（Setter）的关键字 | 无                           | 无                               |
| `propertyName`       | 存取器的名称                 | 必须遵循标识符命名规范       | 无                               |
| `(): ReturnType`     | Getter 的返回值类型注解      | 任意合法类型                 | 可省略（由 TypeScript 自动推断） |
| `(value: ParamType)` | Setter 的参数及类型注解      | 必须与 Getter 的返回类型兼容 | 无                               |

## 常见配套语法

| 配套语法/规则       | 行为影响                                                     |
| ------------------- | ------------------------------------------------------------ |
| 仅定义 `get`        | 该属性自动成为只读属性，外部尝试赋值会报错                   |
| `get` 与 `set` 同名 | 两者必须同名，共同构成一个完整的存取属性                     |
| 类型兼容性          | `set` 的参数类型必须与 `get` 的返回类型兼容                  |
| 成员可见性          | `get` 和 `set` 必须具有相同的访问修饰符（如 `public`、`protected`） |

## 代码示例

`get` 和 `set` 常用于实现计算属性、数据验证或懒加载：

```typescript
class Circle {
  private _radius: number;

  constructor(radius: number) {
    this._radius = radius;
  }

  get radius(): number { // 获取半径
    return this._radius;
  }

  set radius(value: number) { // 设置半径，并验证非负
    if (value < 0) throw new Error("Radius cannot be negative");
    this._radius = value;
  }

  get area(): number { // 计算属性：面积（只读）
    return Math.PI * this._radius ** 2;
  }
}

const circle = new Circle(5);
console.log(circle.area); // 像访问属性一样获取计算后的面积
circle.radius = 10; // 像赋值一样触发 setter 的验证逻辑
```

## `get` 与 `readonly` 的区别

### 定义的区别

- `readonly`

  是一个**修饰符**。它直接作用于类的属性声明上，表示该属性在初始化（如在构造函数中）之后，其引用或值不可被重新赋值。它是对属性本身的一种“只读锁定”。

- `get`

  是一个**存取器关键字**。它定义了一个方法，但允许**以属性访问的语法**来调用。它并不直接锁定某个属性，而是通过执行一段函数逻辑来动态返回一个值。

### 值的来源与动态性

- `readonly`

  存储的是一个**静态的值**。该值在对象创建时被设定，之后保持不变。

- `get`

  返回的是一个**动态计算的结果**。每次访问该属性时，`get` 内部的代码都会重新执行，因此返回的值可以随着对象内部其他状态的变化而变化。

### 语法成分

| 语法成分         | 作用描述               | 数据类型要求   | 可选写法                         |
| ---------------- | ---------------------- | -------------- | -------------------------------- |
| `readonly`       | 声明只读属性的修饰符   | 置于属性声明前 | 无                               |
| `get`            | 声明取值器的关键字     | 置于方法名前   | 无                               |
| `(): ReturnType` | `get` 的返回值类型注解 | 任意合法类型   | 可省略（由 TypeScript 自动推断） |

### 常见配套语法

| 配套语法/规则         | 行为影响                                   |
| --------------------- | ------------------------------------------ |
| `readonly` 属性初始化 | 必须在声明时或构造函数中完成赋值，否则报错 |
| `get` 无参数          | `get` 方法不允许接受任何参数               |
| 仅 `get` 无 `set`     | 该属性在外部表现为只读，尝试赋值会报错     |
| `get` 与 `set` 同名   | 两者必须同名，共同构成一个完整的存取属性   |

### 代码示例

```typescript
class Example {
  // readonly：直接锁定属性，值在构造时确定，不可更改
  readonly id: number;

  // 私有属性，作为 get 的数据源
  private _radius: number;

  constructor(id: number, radius: number) {
    this.id = id; // 初始化只读属性
    this._radius = radius;
  }

  // get：动态计算属性，每次访问都会重新计算
  get area(): number {
    return Math.PI * this._radius ** 2;
  }
}

const example = new Example(1, 5);
console.log(example.id); // 1（静态值）
console.log(example.area); // 78.53...（动态计算值）
// example.id = 2; // 报错：无法分配到 "id" ，因为它是只读属性
```

# interface 介绍

## 语法格式

`interface` 关键字用于定义对象的形状（Shape），即规定对象必须包含哪些属性、方法以及它们的类型。

```typescript
interface User {
  id: number; // 声明普通必填属性，类型为 number
  name: string; // 声明普通必填属性，类型为 string
  age?: number; // 声明可选属性，实际类型等价于 number | undefined
  readonly role: string; // 声明只读属性，初始化后不可修改
  greet(): string; // 声明方法签名，规定返回值类型
}
```

## 语法成分详解

| 语法成分                | 作用描述                 | 数据类型要求                         | 可选写法                                          |
| ----------------------- | ------------------------ | ------------------------------------ | ------------------------------------------------- |
| `interface`             | 声明接口的关键字         | 无                                   | 无                                                |
| `InterfaceName`         | 自定义的接口名称         | 必须遵循标识符命名规范（大驼峰命名） | 无                                                |
| `属性名: 类型`          | 声明普通必填属性         | 任意合法类型                         | 无                                                |
| `属性名?: 类型`         | 声明可选属性             | 任意合法类型                         | 无                                                |
| `readonly 属性名: 类型` | 声明只读属性             | 任意合法类型                         | 无                                                |
| `方法名(参数): 返回值`  | 声明方法签名             | 参数与返回值需明确类型               | 也可使用函数表达式语法（如 `方法名: () => void`） |
| `[key: string]: 类型`   | 声明索引签名（动态属性） | 键名类型必须为 string 或 number      | 无                                                |

## 常见配套语法

| 配套语法        | 行为影响                                             |
| --------------- | ---------------------------------------------------- |
| `extends`       | 实现接口继承，子接口将拥有父接口的所有属性和方法     |
| `implements`    | 强制类实现接口定义的所有属性和方法                   |
| 声明合并        | 同名接口会自动合并属性，常用于扩展第三方库的类型定义 |
| `&`（交叉类型） | 可将接口与其他类型合并，生成包含所有成员的新类型     |

## 代码示例

### 控制类

`interface` 关键字常与 `extends`、`implements` 配合使用，构建清晰的类型约束体系：

```typescript
// 定义基础接口
interface Identifiable {
  id: number;
}

// 继承基础接口并扩展新属性
interface User extends Identifiable {
  name: string;
}

// 类实现接口，必须提供所有定义的属性和方法
class Admin implements User {
  id: number;
  name: string;
  role: string;

  constructor(id: number, name: string, role: string) {
    this.id = id;
    this.name = name;
    this.role = role;
  }
}
```

### 控制对象

接口也可以定义对象的格式，这是它可以与 `type` 互换。

```ts
interface PersonInterface {
	name: string,
    age: number,
    hobby?: string
}

const p: PersonInterface = {
    name: "张三",
    age: 18,
    hobby: "篮球"
}
```

## 接口合并

当多次定义同一个接口时，这个接口的属性和方法会合并。

```ts
interface PersonInterface {
    name: string,
    age: number
}

interface PersonInterface {
	hobby: string
}

// 此时 PersonInterface 要求必须有三个属性
```

## 与 `type` 的区别

1. 相同点

   `interface` 和 `type` 都可以用于定义**对象结构**，两者在许多场景中是可以互换的。

2. 不同点

   - `interface`

     更专注于定义**对象**和**类**的结构，支持**继承**、**合并**。

   - `type`

     可以定义**类型别名**、**联合类型**、**交叉类型**，但不支持继承和自动合并。

## 与抽象类的区别

1. 相同点

   都用于定义一个**类的格式**（应该遵循的契约）

2. 不相同点

   - 接口

     **只能描述结构**，**不能有任何实现代码**，一个类可以实现多个接口。

   - 抽象类

     既可以包含**抽象方法**，也可以包含**具体方法**，一个类只能继承一个抽象类。

# 泛型

## 定义与本质

泛型（Generics）是 TypeScript 中实现类型参数化的核心机制。其本质是引入“类型变量”（通常用 `T`、`K`、`V` 等表示），在定义函数、接口或类时不预先指定具体的类型，而在使用时再动态绑定具体类型。

- 核心价值

  泛型在保持代码高度复用性的同时，严格保留了类型信息，避免了使用 `any` 类型导致的类型安全丢失问题。

- 类型安全

  编译器会在编译阶段根据传入的具体类型进行严格的类型检查，确保输入与输出的类型一致性。

## 核心作用

| 作用维度           | 详细说明                                                     |
| ------------------ | ------------------------------------------------------------ |
| **代码复用**       | 无需为每种数据类型编写重复的逻辑，一份代码即可适配多种类型。 |
| **类型安全**       | 替代 `any` 类型，在编译期捕获类型错误，避免运行时崩溃。      |
| **保留类型信息**   | 确保函数的参数类型与返回值类型存在明确的关联，而非丢失信息的 `any`。 |
| **增强代码表达力** | 明确表达数据结构（如 API 响应、通用容器）的通用性与约束条件。 |

## 基础语法

### 泛型函数

在函数名后使用尖括号 `<T>` 声明类型变量，并在参数和返回值中使用该变量。

```typescript
function identity<T>(arg: T): T { // <T>：声明类型变量 T；(arg: T)：参数类型为 T；: T：返回值类型为 T
  return arg; // 返回与输入相同类型的值
}

const num = identity<number>(42); // 显式指定 T 为 number
const str = identity("hello"); // 自动推断 T 为 string
```

### 泛型接口

在接口名后声明类型变量，使接口能够适配不同的数据结构。

```typescript
interface ApiResponse<T> { // <T>：声明类型变量 T
  code: number; // 固定属性
  data: T; // 核心数据字段的类型由使用者决定
}

const userResponse: ApiResponse<{ name: string }> = { // 指定 T 为具体对象类型
  code: 200,
  data: { name: "Alice" }
};
```

### 泛型类

在类名后声明类型变量，使类的属性和方法能够处理多种类型的数据。

```typescript
class DataStore<T> { // <T>：声明类型变量 T
  private data: T[] = []; // 使用 T 定义数组属性

  addItem(item: T): void { // 方法参数类型为 T
    this.data.push(item);
  }

  getItem(index: number): T { // 方法返回值类型为 T
    return this.data[index];
  }
}

const numberStore = new DataStore<number>(); // 实例化时指定 T 为 number
numberStore.addItem(10);
```

## 泛型的高级特性

### 泛型约束

Generic Constraints。使用 `extends` 关键字限制类型变量必须满足特定的结构或条件，防止传入不具备所需属性的类型。

```typescript
interface HasLength {
  length: number; // 定义必须包含 length 属性的接口
}

function logLength<T extends HasLength>(arg: T): void { // <T extends HasLength>：约束 T 必须具有 length 属性
  console.log(arg.length); // 安全访问 length 属性
}

logLength("hello"); // 正确：字符串有 length 属性
logLength([1, 2, 3]); // 正确：数组有 length 属性
// logLength(123); // 错误：数字没有 length 属性
```

### 多类型参数与键约束

Keyof Constraint。支持同时声明多个类型变量，并利用 `keyof` 约束类型参数为对象的键。

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] { // <T, K extends keyof T>：约束 K 必须是 T 的键
  return obj[key]; // 确保 key 是 obj 的有效属性
}

const user = { name: "Alice", age: 30 };
const name = getProperty(user, "name"); // 正确：name 是 user 的属性
// const invalid = getProperty(user, "email"); // 错误：email 不是 user 的属性
```

### 泛型默认值

为类型参数设置默认类型，当未指定或未推断出具体类型时使用。

```typescript
function createPair<S = string, T = number>(v1: S, v2: T): [S, T] { // <S = string, T = number>：设置默认类型
  return [v1, v2];
}

const pair = createPair("hello", 42); // 自动推断 S 为 string，T 为 number
```

## 内置泛型工具类型

TypeScript 提供了一系列内置的泛型工具类型，用于简化常见的类型操作：

| 工具类型       | 作用描述                         | 示例说明                                                     |
| -------------- | -------------------------------- | ------------------------------------------------------------ |
| `Partial<T>`   | 将 T 的所有属性变为可选          | `Partial<User>` → `{ name?: string; age?: number }`          |
| `Readonly<T>`  | 将 T 的所有属性变为只读          | `Readonly<User>` → `{ readonly name: string; readonly age: number }` |
| `Record<K, T>` | 构造一个对象类型，键为 K，值为 T | `Record<string, number>` → `{ [key: string]: number }`       |
| `Pick<T, K>`   | 从 T 中挑选部分属性 K 构造新类型 | `Pick<User, "name">` → `{ name: string }`                    |

## 注意事项

1. 优先使用类型推断

   在大多数情况下，TypeScript 编译器能够根据传入的参数自动推断泛型类型，无需显式指定，以保持代码简洁。

2. 合理使用约束

   当泛型类型需要具备特定能力（如访问属性、调用方法）时，务必使用 `extends` 进行约束，避免在函数体内进行不安全的类型断言。

3. 避免过度复杂化

   泛型参数应尽量精简，类型参数越少越好。若单个参数即可解决问题，无需引入多个类型变量。

4. 命名规范

   遵循社区约定，通用类型使用 `T`，键值对使用 `K` 和 `V`，集合元素使用 `E`，以提升代码可读性。

# 类型声明文件

## 定义与本质

类型声明文件（Declaration Files）是以 `.d.ts` 为扩展名的特殊 TypeScript 文件。其核心本质是**仅包含类型信息，不包含任何可执行的逻辑代码**。

- 编译特性

  `.d.ts` 文件在编译时不会生成任何 `.js` 文件，仅在编译阶段为 TypeScript 编译器提供类型检查与智能提示服务。

- 核心作用

  主要用于为现有的 JavaScript 代码（如第三方库、遗留项目）补充类型定义，使 TypeScript 能够理解并安全地使用这些无类型的代码。

## 核心应用场景

| 场景                 | 详细说明                                                     |
| -------------------- | ------------------------------------------------------------ |
| **第三方 JS 库支持** | 为没有内置类型的 JavaScript 库提供类型声明，获得 IDE 的代码补全与类型检查。 |
| **项目类型共享**     | 在大型项目中提取公共类型（如接口、类型别名），实现跨文件的类型复用。 |
| **JS 项目迁移**      | 在将 JavaScript 项目逐步迁移至 TypeScript 时，为已有的 `.js` 文件提供类型注解。 |
| **全局变量声明**     | 为通过 `<script>` 标签引入的全局变量或挂载在 `window` 上的属性提供类型描述。 |

## 与使用方式

### 基础类型声明

使用 `declare` 关键字声明全局变量、函数或类，告知编译器这些实体已存在于运行环境中。

```typescript
// 声明全局变量
declare const API_BASE_URL: string; 

// 声明全局函数
declare function formatDate(timestamp: number): string; 
```

### 模块声明

为独立的 JavaScript 模块提供类型定义，通常使用 `declare module` 包裹。

```typescript
declare module 'my-library' { 
  export function doSomething(value: string): void; 
  export interface Options { 
    size: number; 
    color: string; 
  } 
} 
```

### 共享类型定义

在 `.d.ts` 文件中定义并导出类型，供项目中的 `.ts` 文件导入使用。

```typescript
// types.d.ts
export interface User { 
  id: number; 
  name: string; 
} 

// main.ts
import { User } from './types'; 
const user: User = { id: 1, name: 'Alice' }; 
```

## 关键语法成分详解

| 语法成分             | 作用描述                       | 数据类型要求                         | 可选写法                         |
| -------------------- | ------------------------------ | ------------------------------------ | -------------------------------- |
| `declare`            | 声明全局变量、函数或类的关键字 | 仅用于类型声明，不产生实际运行时代码 | 无                               |
| `export`             | 导出类型、接口或声明的变量     | 用于模块化共享类型                   | 无                               |
| `declare module`     | 声明外部模块的类型定义         | 模块名需与导入路径一致               | 无                               |
| `interface` / `type` | 定义对象结构或类型别名         | 任意合法类型                         | 在 `.d.ts` 中无需 `declare` 修饰 |

## 常见配套机制

| 配套机制               | 行为影响                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **自动加载**           | 导入 `.js` 文件时，TypeScript 会自动查找并加载同名的 `.d.ts` 文件。 |
| **@types 组织**        | 社区维护的 DefinitelyTyped 仓库提供了大量常用库的类型定义，可通过 `npm install @types/库名` 安装。 |
| **tsconfig.json 配置** | 通过 `include` 或 `typeRoots` 配置项，可指定 TypeScript 编译器自动扫描和加载声明文件的目录。 |
| **声明合并**           | 多个同名接口或命名空间的声明会自动合并，常用于扩展第三方库的全局类型（如扩展 `Window` 对象）。 |

## 注意事项

- 优先使用社区类型

  在使用第三方 JavaScript 库前，应先检查是否存在 `@types/库名` 包，避免重复造轮子。

- 保持声明文件纯净

  `.d.ts` 文件中严禁包含任何函数体、变量赋值等实现代码，仅保留类型签名。

- 合理组织目录

  在大型项目中，建议将自定义的 `.d.ts` 文件集中存放在 `typings` 或 `types` 目录下，并在 `tsconfig.json` 中统一配置引用路径。

- 善用声明合并

  当需要为全局对象（如 `window`）添加自定义属性时，利用声明合并机制扩展全局接口，而非修改原始库的类型定义。
