# 类型声明

## 变量

`变量名: 类型`

```ts
let a: string = "";
```

> 推荐基础类型用小写。

## 函数

```ts
function (param: 类型): 返回值类型 {}
```

## 字面量类型

比如 `let a: "hello"`，相当于 a 只能存 hello。

# 类型总览

## js 中的数据类型

1. `string`
2. `number`
3. `boolean`
4. `null`
5. `undefined`
6. `bigint`
7. `symbol`
8. `object`

其中 `object` 包含：`Array`、`Function`、`Date`、`Error` 等。

在 JavaScript 中的这些内置构造函数：`Number`、`String`、`Boolean`，它们用于创建对应的**包装对象**，在日常开发时**很少使用**，在 TypeScript 中也是同理，所以在 TypeScript 中进行类型声明时，通常都是用小写的 `number`、`string`、`boolean`。

> **ts 的 object 解释**
>
> `object`（小写）的含义是：所有**非原始类型**，可存储：对象、函数、数组等。
>
> 由于限制的范围**比较宽泛**，在实际开发中使用的**相对较少**。
>
> ```typescript
> let a: object // a的值可以是任何【非原始类型】，包括：对象、函数、数组等
> 
> // 以下代码，是将【非原始类型】赋给a，所以均符合要求
> a = {}
> a = { name: '张三' }
> a = [1, 3, 5, 7, 9]
> a = function () {}
> a = new String('123')
> class Person {}
> a = new Person()
> 
> // 以下代码，是将【原始类型】赋给a，有警告
> a = 1         // 警告：不能将类型“number”分配给类型“object”
> a = true      // 警告：不能将类型“boolean”分配给类型“object”
> a = '你好'    // 警告：不能将类型“string”分配给类型“object”
> a = null      // 警告：不能将类型“null”分配给类型“object”
> a = undefined // 警告：不能将类型“undefined”分配给类型“object”
> ```
>
> 如果是大写的 `Object`，那能存储的就是能调用到 `Object` 方法的值。也就是只有 `null` 和 `undefined` 不能存。

## ts 中的数据类型

1. 上述所有 JavaScript 类型
2. 两个用于自定义类型的方式：`type`、`interface`。
3. 六个新类型

## 六个新类型

### `any`

任意类型。一旦变量类型设置为 `any`，就意味着放弃了对该变量的类型检查。

`any` 类型的变量可以赋值给任意类型的变量。

### `unknown`

是安全的 `any`，不能赋值给其他变量。使用了 `unknown` 的变量调用任何方法都会报错，但是 `any` 不会。不想报错则使用断言。

```ts
(value as String).toUpperCase()
```

### `never`

任何值都不是，不能有任何值，`undefined`、`null` 等都不行。一般不用来限制变量，而用于限制函数的返回值。

但是，js 的函数即便不写 `return` 也会返回一个 `undefined`。因此，这个函数必须不能顺利进行完。

```ts
function fn(): never {
    throw new Error("程序异常")
}

function fn():never {
    fn()
}
```

`never` 一般由编辑器自动推断。

```ts
let a: string = "111";

if (a instanceof string) {
    console.log(a)
} else {
	console.log(a)
}
```

在 `else` 下面的 `a` 就是 `never`。

### `void`

通常用于函数返回值声明，即函数不返回任何值，调用者也不应该依赖其返回值进行任何操作。

```ts
function fn(): void {
    console.log(111)
}

let result = fn();
if (result) {} // 在判断内部出错，因为不能使用 void 返回值操作，但是 undefined 是可以的
```

编码者没有编写 `return` 去指定一个函数的返回值，所以这个函数是没有**显式返回值**的，但会有一个**隐式返回值**，就是 `undefined`；即：虽然函数返回类型为 `void`，但也是可以接受 `undefined` 的。

简单记：`undefined` 是 `void` 可以接受的一种“空”。

1. `void` 是一个广泛的概念，用来表达“空”，而 `undefined` 则是这种“空”的具体实现之一。
2. 因此可以说 `undefined` 是 `void` 能接受的“空”状态的一种具体形式。
3. 换句话说：`void` 包含 `undefined`，但 `void` 表达的语义超越了单纯的 `undefined`，它是一种意图上的约定，而不仅仅是特定值的限制。

从语法上讲：函数是可以返回 `undefined` 的，至于显示返回，还是隐式返回。

从语义上讲：函数调用者不应关心函数返回的值，也不应依赖返回值进行任何操作，即使返回了 `undefined` 值。

### `tuple`

元组，一种特殊的数组类型，储存固定数量的元素，并且每个元素的类型是已知的且可以不同。

元组用于精确描述一组值得类型，`?` 表示可选元素。

```ts
// 第一个元素必须是 string 类型，第二个元素必须是 number 类型。
let arr1: [string, number]

// 第一个元素必须是 number 类型，第二个元素是可选的，如果存在，必须是 boolean 类型。
let arr2: [number, boolean?]

// 第一个元素必须是 number 类型，后面的元素可以是任意数量的 string 类型
let arr3: [number, ...string[]]
```

### `enum`

可以定义一组命名的常量。增强代码的可读性和可维护性。

   - 原始类型

     如 `number`、`string`、`boolean`，在 JavaScript 中是简单数据类型，它们在内存中占用空间少，处理速度快。

2. 自动装箱

   JavaScript 在必要时会自动将原始类型包装成对象，以便调用方法或访问属性

# 断言

## 定义

类型断言（Type Assertion）是 TypeScript 中用于手动指定某个值具体类型的语法机制。其本质是向编译器传递类型信息，绕过编译器的自动类型推断，使原本不兼容的代码通过类型检查。

1. 非运行时转换

   断言仅在编译阶段起作用，不会改变值的实际类型，也不会进行任何运行时的数据检查或解构。

2. 核心前提

   断言要求值的实际类型与断言类型必须兼容（即一方是另一方的子类型），不能将完全无关的类型进行断言。

## 核心作用

1. 细化 DOM 元素类型

   在网页开发中，`document.getElementById` 等 API 默认返回宽泛的 `HTMLElement` 或 `null`。通过断言，可以将其细化为具体的 `HTMLInputElement` 等子类，从而安全访问特定属性（如 `value`）。

2. 处理 API 响应数据

   在前后端协作中，从接口获取的数据通常为 `any` 或 `unknown` 类型。通过断言，可以将其指定为具体的业务接口类型，从而获得完整的代码提示与类型检查。

3. 解决对象字面量严格检查

   当对象字面量包含目标类型未定义的多余属性时，直接赋值会报错。使用断言可以绕过这种严格的字面量检查。

4. 指定未知类型的变量

   将 `unknown` 或联合类型的变量断言为具体的子类型，以便进行后续操作。

## 语法格式

### `as` 语法

```typescript
const value = someValue as TargetType;
// someValue：需要被断言的原始值或表达式。
// TargetType：目标类型。必须与原始值的实际类型兼容（互为子类型关系）。
// value：断言后的变量，编译器将视其为 TargetType 类型。
```

### 非空断言

```typescript
const value = maybeNull!;
// maybeNull：可能为 null 或 undefined 的值。
// !：非空断言操作符，置于变量或表达式之后，告诉编译器该值一定不为空。
```

### const 断言

```typescript
const config = { apiUrl: 'https://api.example.com', timeout: 5000 } as const;
// as const：将字面量推断为不可变的只读类型，锁定值永不改变。
```

### 尖括号

```ts
const value = <类型>someValue
```



## 断言类型详解

| 断言类型     | 语法             | 核心作用                   | 典型应用场景                             |
| ------------ | ---------------- | -------------------------- | ---------------------------------------- |
| 类型断言     | `value as Type`  | 将值断言为另一种兼容类型   | DOM 元素细化、API 响应处理、父类转子类   |
| 非空断言     | `value!`         | 排除 `null` 和 `undefined` | 可选属性访问、确定 DOM 元素存在          |
| const 断言   | `value as const` | 将字面量变为只读不可变类型 | 常量配置对象、字面量联合类型             |
| 确定赋值断言 | `let x!: Type`   | 声明变量稍后会被明确赋值   | 类属性在构造函数或 init 方法中延迟初始化 |

## 双重断言

当需要将两个完全无关的类型进行转换时，单次断言会报错。此时需通过 `unknown` 或 `any` 作为中介进行两次断言：

```typescript
const num = "hello" as unknown as number; 
// 第一次断言为 unknown（所有类型的父类型），第二次断言为目标类型。
// 注意：此操作极其危险，极易在运行时引发崩溃，应尽量避免。
```

>这相当于告诉 TypeScript “我知道我在做什么”，但不会进行运行时检查，务必确保数据形状正确。

## 注意事项

1. 优先使用类型守卫

   在处理 DOM 元素或 API 数据时，优先使用 `instanceof`、`typeof` 或自定义类型守卫函数进行运行时校验，而非盲目使用断言。

2. 仅在 100% 确定时使用

   断言本质上是“对编译器说谎”，滥用断言会掩盖潜在的运行时错误，削弱 TypeScript 的类型安全优势。

3. JSX 环境限制

   在 `.tsx` 文件中，由于尖括号语法 `<Type>` 会与 JSX 标签冲突，必须统一使用 `as` 语法进行断言。

# 对象声明

## 声明方式概览

在 TypeScript 中，为对象声明属性主要有三种标准化的方式：接口（interface）、类型别名（type）以及内联类型注解。这三种方式均基于 TypeScript 的结构化类型系统，只关注对象的结构（属性和方法）而非具体的实现。

| 语法成分                | 作用描述         | 可选值/修饰符                    |
| ----------------------- | ---------------- | -------------------------------- |
| `属性名: 类型`          | 声明普通必填属性 | 基础类型、自定义类型、联合类型等 |
| `属性名?: 类型`         | 声明可选属性     | 赋值时可省略该属性               |
| `readonly 属性名: 类型` | 声明只读属性     | 初始赋值后无法被重新赋值         |

## 接口声明

接口（interface）主要用于描述**对象的结构**，定义对象应该具有的属性和方法。接口支持声明合并（Declaration Merging），即多次声明同名接口会自动合并属性。

### 基础语法

```typescript
interface User {
  id: number; // id：普通必填属性，类型为 number
  name: string; // name：普通必填属性，类型为 string
  age?: number; // age：可选属性，实际类型等价于 number | undefined
  readonly role: string; // role：只读属性，初始化后不可修改
}
```

## 类型别名声明

类型别名（type）用于给任何类型（包括对象类型、联合类型等）命名。与接口不同，类型别名一旦定义便无法重新打开添加新属性。

### 基础语法

```typescript
type Point = {
  x: number; // x：坐标属性，类型为 number
  y: number; // y：坐标属性，类型为 number
};
```

### 与接口的区别

| 对比维度 | 接口 (interface)          | 类型别名 (type)              |
| -------- | ------------------------- | ---------------------------- |
| 扩展方式 | 使用 `extends` 关键字继承 | 使用 `&` 交叉类型合并        |
| 声明合并 | 支持（同名接口自动合并）  | 不支持（重复定义会报错）     |
| 适用场景 | 描述对象结构、类契约      | 联合类型、元组、复杂类型组合 |

## 内联类型注解

直接在变量声明处编写对象结构，适用于仅使用一次的简单对象类型。

```typescript
const user: { id: number; name: string } = { id: 1, name: 'Alice' };
```

*用逗号或者分号隔开都行。*

## 高级属性声明机制

### 索引签名

Index Signatures，用于声明**动态**属性，当对象的键名无法提前完全确定时使用。

```typescript
interface Dictionary {
  [key: string]: string; // 任意字符串键对应的值必须为 string 类型
}
```

比如一个对象在创建之后还需要添加属性，就要使用索引签名。类似于 python 中的 `__dict__` 的作用。

`[key: string]: string` 里面的才是 `key` 对应的类型。

### 方法声明

对象中的方法可以通过函数声明语法或函数表达式语法进行声明。

```typescript
interface Handler {
  // 方式一：函数声明语法
  onClick(event: Event): void; 
  // 方式二：函数表达式语法（箭头函数形式）
  onSubmit: (data: FormData) => boolean; 
}
```

## 实践规范

1. 优先使用接口

   在描述对象结构时，官方建议优先使用 `interface`，以获得更好的错误提示和扩展性。

2. 按需使用类型别名

   当需要定义联合类型、元组或复杂的工具类型时，使用 `type`。

3. 避免滥用 `any`

   在声明对象属性时，应尽量避免使用 `any` 类型，以保持类型系统的安全性与可预测性。

# 函数声明

TypeScript 在 JavaScript 函数的基础上增加了强大的类型支持。函数声明的核心在于明确指定参数的类型以及返回值的类型。常见的声明方式包括函数声明、函数表达式、箭头函数以及使用类型别名统一定义函数格式。

## 基础函数声明

### 函数声明

Function Declaration。使用 `function` 关键字定义命名函数，参数和返回值需显式标注类型。

```typescript
function add(a: number, b: number): number {
  return a + b;
}
```

### 函数表达式

Function Expression。将匿名函数赋值给变量，变量本身可指定函数类型。

```typescript
const subtract = function(x: number, y: number): number {
  return x - y;
};
```

### 箭头函数

Arrow Function。使用箭头语法定义函数，适用于简短的函数逻辑。

```typescript
const multiply = (a: number, b: number): number => a * b;
```

### 声明函数

```ts
// 说明函数的格式，这个不是箭头函数。这里的箭头表示参数和返回值的分隔符。
let count: (a: number, b: number) => number;

// 形参的名字不一定要对应
count = (x, y) => x + y;
```

## 参数类型详解

### 可选参数

Optional Parameters。在参数名后添加 `?` 表示该参数可以省略。可选参数必须放在必选参数之后。

```typescript
function greet(name: string, greeting?: string): string {
  return `${greeting ?? "Hi"} ${name}`;
}
```

### 默认参数

Default Parameters。为参数设置默认值。当调用时未传递该参数或传递 `undefined` 时，将使用默认值。

```typescript
function log(message: string = "Info"): void {
  console.log(message);
}
```

### 剩余参数

Rest Parameters。使用 `...` 语法将不定数量的参数表示为一个数组。剩余参数的类型必须是数组类型。

```typescript
function sum(...numbers: number[]): number {
  return numbers.reduce((total, n) => total + n, 0);
}
```

## 类型定义与别名

当多个函数具有相同的参数和返回值结构时，可使用类型别名统一定义函数格式，提高代码可读性与复用性。

```typescript
type BinaryOperation = (a: number, b: number) => number;

const add: BinaryOperation = (x, y) => x + y;
const divide: BinaryOperation = (x, y) => {
  if (y === 0) throw new Error("除零");
  return x / y;
};
```

## 函数重载

TypeScript 支持函数重载（Function Overloading），即同一个函数名根据不同的参数类型或数量提供不同的实现。

重载声明需先写多个重载签名（只有类型，没有实现），最后写一个兼容所有重载的实际实现函数。

```typescript
function format(value: string): string;
function format(value: number, digits: number): string;
function format(value: any, digits?: any): string {
  if (typeof value === "string") {
    return value.toUpperCase();
  }
  if (typeof value === "number") {
    return value.toFixed(digits ?? 2);
  }
  return String(value);
}
```


## 最佳实践规范

1. 优先使用类型推断

   对于简单的箭头函数，TypeScript 能够自动推断返回值类型，此时可省略返回值类型注解以保持代码简洁。

2. 明确参数类型

   除非在回调函数等上下文中类型能被明确推断，否则应始终为函数参数显式指定类型，避免隐式 `any`。

3. 合理使用重载

   函数重载适用于参数类型差异较大且逻辑完全不同的场景。若仅参数数量不同，优先考虑可选参数或默认参数。

# 数组声明

在 TypeScript 中，数组的声明与 JavaScript 类似，但增加了严格的类型约束。声明数组的核心在于明确指定数组中元素的类型。常见的声明方式包括“类型加方括号”语法和“数组泛型”语法。

## 基础声明语法

### 类型加方括号

在元素类型后面接上 `[]`，表示由此类型元素组成的一个数组。这是社区最主流、写法最简洁的风格。

```typescript
let numbers: number[] = [1, 2, 3]; // 数组成员只能是数字
let names: string[] = ['Alice', 'Bob']; // 数组成员只能是字符串
```

### 数组泛型

使用数组泛型（Array Generic） `Array<元素类型>` 来声明数组。

```typescript
let numbers: Array<number> = [1, 2, 3];
let names: Array<string> = ['Alice', 'Bob'];
```

## 复杂类型声明

### 联合类型数组

当数组中需要存储多种不同类型的元素时，可使用联合类型。注意括号不可省略。

```typescript
// 数组中每个元素可以是 string 或 number
let arr: (string | number)[] = [1, 'name', 2]; 
```

### 多维数组

一个数组的元素可以是另外一个数组，从而构成多维数组。

```typescript
// 二维数字数组
let matrix: number[][] = [[1, 2, 3], [4, 5, 6]];
```

### 对象数组

结合接口或类型别名，可以声明包含特定结构的对象数组。

```typescript
interface User {
  id: number;
  name: string;
}

let users: User[] = [
  { id: 1, name: 'Alice' },
  { id: 2, name: 'Bob' }
];
```

## 元组

元组类型允许表示一个已知元素数量和类型的数组，各元素的类型不必相同。元组严格限制元素的位置与类型。

```typescript
let tuple: [string, number];
tuple = ['hello', 10]; // 正确
// tuple = [10, 'hello']; // 错误：类型不匹配
```

## 只读数组

使用 `ReadonlyArray<类型>` 或 `readonly 类型[]` 声明只读数组。只读数组禁止使用任何会修改数组内容的方法（如 `push`、`pop`、`splice` 等）。

```typescript
let readonlyArr: readonly number[] = [1, 2, 3];
// readonlyArr[0] = 10; // 错误：索引签名仅允许读取
// readonlyArr.push(4); // 错误：属性“push”不存在
```

## 实践规范

1. 优先使用“类型加方括号”语法

   在绝大多数场景下，`类型[]` 的写法比泛型 `Array<类型>` 更简洁直观。

2. 避免使用 `any[]`

   除非处理完全未知结构的极端遗留数据，否则应尽量避免使用 `any[]`，以保持类型系统的安全性与可预测性。

3. 善用接口定义对象数组

   当数组元素为复杂对象时，优先提取接口或类型别名，提高代码的可维护性与复用性。

# 枚举

## 定义

枚举（Enum）是 TypeScript 提供的一种特殊的数据类型，允许为一组相关的命名常量定义一个集合。枚举的核心价值在于为数值或字符串赋予有意义的名称，从而消除代码中的“魔法值”，提升代码的可读性与可维护性。

## 分类与特性

### 数字枚举

Numeric Enums。默认情况下，枚举成员会从 `0` 开始自动递增赋值。支持自定义初始值，后续成员会基于前一个值依次递增。数字枚举支持“**反向映射**”，即可以通过值反查到键名。

```typescript
enum Direction {
  Up,    // 默认值为 0
  Down,  // 1
  Left,  // 2
  Right  // 3
}

// 反向映射示例
console.log(Direction[0]); // 输出: "Up"
console.log(Direction.Up); // 输出：0
```

### 字符串枚举

字符串枚举（String Enums）的每个成员都必须使用字符串字面量或另一个字符串枚举成员进行显式初始化。字符串枚举不支持自动递增，也不支持反向映射。

```typescript
enum LogLevel {
  Debug = "DEBUG",
  Info = "INFO",
  Warn = "WARN",
  Error = "ERROR"
}
```

### 异构枚举

Heterogeneous Enums。枚举中可以混合字符串和数字成员，但除非有特殊的运行时需求，否则不推荐这种写法，容易导致类型混乱。

```typescript
enum BooleanLike {
  No = 0,
  Yes = "YES"
}
```

## 高级枚举特性

### 常量枚举

Const Enums。在枚举定义前添加 `const` 修饰符。常量枚举在编译阶段会被完全移除，所有引用处会被直接内联替换为具体的值，从而减少运行时的额外开销。

```typescript
const enum Status {
  Success = 200,
  NotFound = 404
}
// 编译后直接使用 200 和 404，不会生成 Status 对象
```

### 计算属性与常量成员

枚举成员的值可以是常量（如字面量、其他常量成员），也可以是计算属性（如函数调用、位运算）。若成员使用了计算属性，其后的成员必须显式初始化，不能依赖自动递增。

## 应用场景

| 场景               | 作用描述                                     |
| ------------------ | -------------------------------------------- |
| **业务状态管理**   | 替代硬编码的数字或字符串，使状态流转逻辑清晰 |
| **API 错误码管理** | 统一管理后端返回的错误码，便于映射提示信息   |
| **权限位标志**     | 利用位运算（`, ` `&`）组合和检查多种权限     |
| **多语言/国际化**  | 统一定义语言区域代码，避免拼写错误           |

## 注意事项

1. 优先使用字符串枚举

   在大多数业务场景中，字符串枚举比数字枚举更具可读性，且在调试时能直接输出有意义的值，避免数字带来的歧义。

2. 避免滥用反向映射

   虽然数字枚举支持反向映射，但在实际业务中频繁使用可能导致逻辑复杂化，应谨慎使用。

3. 替代方案

   如果不需要枚举的某些特性（如反向映射），也可以考虑使用 `as const` 断言的对象字面量来替代枚举，以获得更灵活的类型推导。

```typescript
// 使用 as const 替代枚举的示例
const Colors = {
  Red: "RED",
  Green: "GREEN",
  Blue: "BLUE"
} as const;

type Color = keyof typeof Colors; // "Red" | "Green" | "Blue"
```

# type 介绍

## 语法格式

`type` 关键字用于为任意类型（包括基础类型、对象结构、联合类型等）创建一个自定义的命名别名。

```typescript
type ID = number; // 为基础类型创建别名

type User = { // 为对象结构创建别名
  id: ID; // 使用刚刚定义的 ID 类型别名
  name: string; // 定义普通必填属性
  age?: number; // 定义可选属性
};

type StringOrNumber = string | number; // 为联合类型创建别名

type LogFun = () => void; // 定义一个函数类
```

> 使用类型声明限制函数返回值为 `void` 时，**不会严格要求函数返回空**。
>
> ```ts
> type LogFun = () => void;
> 
> let fn: LogFun = () => 666; // 这个是可以的
> ```
>
> 虽然确实拿得到返回值，但是在语法上不应该对其进行任何操作，比如逻辑判断之类的。
>
> 这么设置是为了照顾 lambda 语法。
>
> ```ts
> const src = [1, 2, 3];
> const dst = [0];
> src.forEach((v) => dst.push(v));
> ```
>
> `push` 方法会返回新数组的长度，而回调函数要求返回值为 `void`，如果真的严格要求，那这个就必须写 `{}`。

## 语法成分详解

| 语法成分         | 作用描述                           | 数据类型要求                                   | 可选写法 |
| ---------------- | ---------------------------------- | ---------------------------------------------- | -------- |
| `type`           | 声明类型别名的关键字               | 无                                             | 无       |
| `TypeName`       | 自定义的类型名称                   | 必须遵循标识符命名规范（大驼峰命名）           | 无       |
| `=`              | 赋值符号，将右侧类型绑定到左侧名称 | 无                                             | 无       |
| `TypeDefinition` | 具体的类型定义内容                 | 任意合法的类型（基础类型、对象、联合、交叉等） | 无       |

## 常见配套语法

| 配套语法              | 行为影响                                                     |
| --------------------- | ------------------------------------------------------------ |
| `&`（交叉类型）       | 将多个类型合并为一个新类型，新类型必须同时满足所有被合并类型的约束 |
| `extends`（条件类型） | 配合 `infer` 关键字，在类型层面进行条件判断与类型推导        |
| `keyof`               | 获取对象类型的所有键名，生成联合类型                         |
| `typeof`              | 获取变量或属性的实际类型，常用于从现有值反推类型             |

## 四、代码示例

`type` 关键字常与 `interface` 配合使用，或用于定义复杂的联合类型：

```typescript
// 定义基础类型别名
type ID = number;
type Name = string;

// 定义对象类型别名
type User = {
  id: ID;
  name: Name;
};

// 定义联合类型别名
type StringOrNumber = string | number;

// 使用交叉类型合并多个类型
type Admin = User & { role: 'admin' | 'super_admin' };

// 使用条件类型进行类型推导
type IsString<T> = T extends string ? true : false;
```

# 环境声明

## 概念

`declare` 是 TypeScript 中用于**环境声明（Ambient Declaration）**的核心关键字。环境声明用于告诉 TypeScript 编译器：某个变量、函数、类或模块在运行时环境中已经存在，但 TypeScript 无法在其源文件中找到该实体的定义。

> 比如我已经加载了 `axios.min.js` 文件，那在我当前的文件中。肯定有 `axios` 这个函数，只是 ts 不知道。因此，我们需要 `declare` 告诉它“这里有一个 `axios` ”函数，可以直接用它。至于是不是真的有，它不关心。

## 作用

1. 描述外部代码的类型

   当使用没有 TypeScript 类型定义的第三方 JavaScript 库时，可通过 `declare` 描述该库的类型信息，使 TypeScript 能够进行类型检查。

2. 声明全局变量

   当运行时环境中存在全局变量（如由 CDN 加载的库注入的变量）时，可通过 `declare` 告知 TypeScript 该变量的存在。

3. 仅存在于编译时

   `declare` 声明的类型信息仅在编译时用于类型检查，编译后的 JavaScript 代码中不会包含任何 `declare` 语句。

`declare` 关键字通常在 `.d.ts` 声明文件中使用，也可在普通的 `.ts` 文件中使用（但会将该文件视为环境声明上下文）。

## 语法格式

### 声明变量

`declare var` 用于声明全局变量。若变量为只读，应使用 `declare const`；若变量为块级作用域，可使用 `declare let`。

```typescript
declare var legacyGlobal: any;                // 声明一个全局变量（函数级作用域）
declare let currentUser: string | null;      // 声明一个可变的全局变量（块级作用域）
declare const API_KEY: string;               // 声明一个只读的全局常量
```

### 声明函数

`declare function` 用于声明全局函数的类型签名。

```typescript
declare function log(message: string): void;        // 声明一个无返回值的函数
declare function getWidget(id: number): Widget;     // 声明一个返回 Widget 的函数
```

函数重载可通过多次声明实现：

```typescript
declare function getWidget(n: number): Widget;
declare function getWidget(s: string): Widget[];
```

### 声明类

`declare class` 用于描述类或类对象的类型。可包含构造函数、属性和方法。

```typescript
declare class Greeter {
    constructor(greeting: string);      // 构造函数
    greeting: string;                   // 属性
    showGreeting(): void;               // 方法
}
```

### 声明枚举

`declare enum` 用于声明全局枚举类型。

```typescript
declare enum LogLevel {
    Debug,
    Info,
    Warning,
    Error
}
```

### 声明命名空间

`declare namespace` 用于描述通过点符号（`.`）访问的类型或值。常用于组织相关的类型。

```typescript
declare namespace myLib {
    function makeGreeting(s: string): string;
    let numberOfGreetings: number;
}

// 嵌套命名空间
declare namespace GreetingLib.Options {
    interface Log {
        verbose?: boolean;
    }
    interface Alert {
        modal: boolean;
        title?: string;
    }
}
```

### 声明模块

`declare module` 用于描述需要被导入的模块的形状。

```typescript
// 完整类型声明
declare module 'lodash' {
    export function chunk<T>(array: T[], size: number): T[][];
    export function debounce(func: Function, wait: number): Function;
}

// 简写声明（无类型信息）
declare module 'some-untyped-module';      // 告诉编译器该模块存在，但不提供类型信息
```

### 声明全局作用域扩展

`declare global` 用于扩展全局对象的类型，例如向 `Window` 接口添加自定义属性。

```typescript
declare global {
    interface Window {
        myCustomGlobal: string;
    }
}
```

### 声明类型

`interface` 和 `type` 本身不需要 `declare` 关键字即可声明全局类型。但在 `.d.ts` 文件中，顶级类型声明通常也使用 `declare` 前缀。

```typescript
// 不需要 declare
interface GreetingSettings {
    greeting: string;
    duration?: number;
}

// 在 .d.ts 文件中可加 declare
declare interface GlobalConfig {
    version: string;
}
```

## 语法成分详解

| 语法成分                      | 作用                                 | 数据类型要求                     | 可选写法                                        |
| :---------------------------- | :----------------------------------- | :------------------------------- | :---------------------------------------------- |
| `declare var`                 | 声明一个全局变量（函数级作用域）     | 任意 TypeScript 类型             | 通常用于遗留代码或 UMD 库                       |
| `declare let`                 | 声明一个可变的全局变量（块级作用域） | 任意 TypeScript 类型             | 当变量值可能在运行时变化时使用                  |
| `declare const`               | 声明一个只读的全局常量               | 任意 TypeScript 类型             | 适用于 API 密钥、环境字符串等不会重新赋值的场景 |
| `declare function`            | 声明一个全局函数的类型签名           | 函数类型（参数类型和返回值类型） | 支持多次声明以实现函数重载                      |
| `declare class`               | 声明一个类的类型                     | 类类型（构造函数、属性、方法）   | 可包含访问修饰符（`public`、`private` 等）      |
| `declare enum`                | 声明一个枚举类型                     | 枚举成员                         | 支持数字枚举和字符串枚举                        |
| `declare namespace`           | 声明一个命名空间，用于组织类型       | 命名空间内的类型和值             | 支持嵌套命名空间                                |
| `declare module`              | 声明一个外部模块的类型               | 模块的导出（`export`）           | 支持简写形式（不提供具体类型）                  |
| `declare global`              | 扩展全局作用域中的类型               | 全局接口或命名空间               | 用于向 `Window` 等全局对象添加属性              |
| `interface`（无需 `declare`） | 声明一个接口类型                     | 对象类型结构                     | 支持 `extends` 继承和可选属性                   |
| `type`（无需 `declare`）      | 声明一个类型别名                     | 任意 TypeScript 类型             | 支持联合类型、交叉类型、元组等                  |

## 配套语法

### 与声明文件

| 配套元素                            | 说明                                             | 行为影响                                                     |
| :---------------------------------- | :----------------------------------------------- | :----------------------------------------------------------- |
| `.d.ts` 文件                        | 声明文件的扩展名，仅包含类型信息，不包含实现代码 | 编译器会识别 `.d.ts` 文件中的类型声明，但不将其编译为 JavaScript |
| `/// <reference />` 指令            | 用于引用其他声明文件                             | 告诉编译器在编译时包含指定的声明文件                         |
| `tsconfig.json` 的 `types` 选项     | 指定编译器包含的类型声明包                       | 控制哪些 `@types/` 包被自动包含                              |
| `tsconfig.json` 的 `typeRoots` 选项 | 指定类型声明文件的查找目录                       | 自定义编译器搜索 `.d.ts` 文件的位置                          |

### 与导入导出

| 配套语法              | 使用场景                             | 行为影响                              |
| :-------------------- | :----------------------------------- | :------------------------------------ |
| `export`              | 在 `declare module` 内部导出类型     | 声明模块的公开 API                    |
| `import`              | 配合 `declare module` 声明的模块使用 | 获得已声明模块的类型支持              |
| `import type`         | 仅导入类型，编译后擦除               | 与 `declare` 配合使用可避免运行时依赖 |
| `export as namespace` | 声明模块在全局作用域中可用           | 用于 UMD 模块的全局类型声明           |

## 代码示例

### 声明全局变量

```typescript
// 假设通过 CDN 加载了 axios，但未安装 @types/axios
declare const axios: {
    get<T = any>(url: string): Promise<{ data: T }>;
    post<T = any>(url: string, data?: any): Promise<{ data: T }>;
};

axios.get("https://api.example.com/data")
    .then(response => console.log(response.data));
```

### 声明外部模块

```typescript
// types.d.ts
declare module "my-utils" {
    export function formatDate(date: Date): string;
    export const VERSION: string;
}

// app.ts
import { formatDate, VERSION } from "my-utils";
console.log(formatDate(new Date()));  // 类型安全，有代码提示
```

### 扩展全局对象

```typescript
// global.d.ts
declare global {
    interface Window {
        __MY_APP_CONFIG__: {
            apiUrl: string;
            timeout: number;
        };
    }
}

// app.ts
const config = window.__MY_APP_CONFIG__;  // TypeScript 识别该属性
console.log(config.apiUrl);
```

### 在 `.d.ts` 文件中声明命名空间

```typescript
// greeter.d.ts
declare namespace GreetingLib {
    interface Options {
        greeting: string;
        duration?: number;
        color?: string;
    }
    function greet(options: Options): void;
    class Greeter {
        constructor(greeting: string);
        greeting: string;
        showGreeting(): void;
    }
}

// app.ts
GreetingLib.greet({ greeting: "Hello", duration: 3000 });
const g = new GreetingLib.Greeter("Hi");
g.showGreeting();
```
