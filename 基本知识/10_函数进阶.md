# 作用域（scope）

## 作用域的定义与本质

作用域是一套规则，用于确定在代码执行期间，变量和其他资源（如函数）在哪些区域可以被访问。其本质是变量和函数的“可访问性”与“生命周期”的管理机制。作用域在代码编译（或解析）阶段就已经确定，与代码的执行顺序无关。

## 作用域的核心作用

- 变量隔离与安全性

  防止不同代码块中的变量命名冲突，避免意外修改全局状态。

- 内存管理

  决定了变量的生命周期。当变量离开其作用域时，JavaScript 引擎的垃圾回收机制会将其标记为可回收，从而释放内存。

- 代码组织与封装

  通过作用域划分代码的逻辑边界，实现模块化开发，隐藏内部实现细节，仅暴露必要的接口。

## 分类与使用规则

JavaScript 采用**词法作用域（静态作用域）**，即变量的作用域在代码编写阶段就已确定，而非在运行时动态决定。

| 对比维度         | 全局作用域<br>（Global Scope）                            | 函数作用域<br>（Function Scope）                     | 块级作用域<br>（Block Scope）                         |
| :--------------- | :-------------------------------------------------------- | :--------------------------------------------------- | :---------------------------------------------------- |
| **定义**         | 在任何函数和代码块之外声明的变量。                        | 在函数内部声明的变量。                               | 由 `{}` 包裹的代码块（如 `if`、`for`、`while`）内部。 |
| **生命周期**     | 贯穿整个页面/程序，直到页面关闭或程序退出。               | 仅在函数执行期间存在，执行完毕后销毁。               | 仅在代码块执行期间存在。                              |
| **声明方式**     | `var` / `let` / `const`                                   | `var` / `let` / `const`（但 `var` 特有函数作用域）。 | `let` / `const`（`var` 无视块级作用域）。             |
| **变量提升**     | `var` 声明提升，`let`/`const` 不提升。                    | `var` 声明提升到函数顶部，`let`/`const` 不提升。     | `let`/`const` 不提升，存在**暂时性死区（TDZ）**       |
| **是否污染全局** | 会，成为 `window`（浏览器）或 `global`（Node.js）的属性。 | 不会。                                               | 不会。                                                |
| **典型风险**     | 命名冲突、内存泄漏、难以维护。                            | 变量在函数外无法访问（封装性）。                     | 变量在块外无法访问（更精细的隔离）。                  |
| **ES6 推荐度**   | 尽量少用，避免全局污染。                                  | 可用，但推荐用 `let`/`const` 替代 `var`。            | **推荐**，优先使用 `let` 和 `const` 实现块级隔离。    |

## 变量查找机制

当在某个作用域中访问一个变量时，JavaScript 引擎会按照以下顺序进行查找：

1. 当前作用域查找

   首先在当前执行上下文的词法环境中查找该变量。

2. 向上层作用域查找

   如果在当前作用域未找到，引擎会沿着**作用域链**向外层（父级）作用域逐级查找。

3. 全局作用域查找

   一直查找到全局作用域。

4. 抛出错误

   如果在全局作用域中仍未找到该变量，则抛出 `ReferenceError: xxx is not defined`。

## 作用域链的构建规则

*作用域链（Scope Chain）。*

- 函数的作用域链在函数**创建时**（而非调用时）就已经确定。
- 内部函数可以访问外部函数的变量，但外部函数无法访问内部函数的变量（单向访问）。

## 关键概念辨析

- 词法作用域 vs 动态作用域

  JavaScript 采用词法作用域，变量的作用域由代码的静态结构决定。动态作用域（如 Bash 脚本）则根据代码的运行时的调用栈来决定变量的作用域。

- 变量提升（Hoisting）

  仅指变量声明（`var`）或函数声明被移动到作用域顶部的行为，赋值操作不会提升。`let` 和 `const` 虽然也存在提升，但由于暂时性死区的存在，在声明前不可访问。

- 闭包（Closure）

  当一个内部函数被返回到外部并被调用时，它能够“记住”并访问其词法作用域中的变量，即使该内部函数在其词法作用域之外执行。闭包是作用域链和函数作为一等公民特性的直接产物。

## 注意事项

- 优先使用 `const`

  对于不需要重新赋值的变量，始终使用 `const`，以明确表达意图并防止意外修改。

- 避免使用 `var`

  `var` 的函数作用域和提升行为容易导致难以追踪的 Bug，现代 JavaScript 开发中应全面使用 `let` 和 `const`。

- 最小化全局变量

  使用模块（ES Modules）、IIFE（立即调用函数表达式）或块级作用域来封装逻辑，减少全局命名空间的污染。

- 注意暂时性死区

  在使用 `let` 和 `const` 时，确保在声明语句之后才访问变量，避免在块级作用域的开头引用尚未声明的变量。

# 栈与堆

## 定义与本质

在 JavaScript 的内存管理机制中，栈（Stack）和堆（Heap）是两块用途截然不同的内存区域，共同构成了程序的运行时内存空间。

- 栈（Stack）

  一块连续、有序的内存区域，由 JavaScript 引擎自动管理。它遵循“后进先出”（LIFO）的原则，主要用于存储代码执行过程中的上下文信息和基础数据类型。

- 堆（Heap）

  一块不连续、庞大的内存区域，通常由垃圾回收器（Garbage Collector）管理。它主要用于存储动态分配的复杂数据结构（如对象、数组、函数等）。

## 核心作用

### 栈的作用

- 管理执行上下文

  存储函数调用时的执行上下文（Execution Context），包括局部变量、函数参数和返回地址。

- 高效存取基础数据

  由于栈内存是连续的且大小固定，基础数据类型的存取速度极快。

- 自动内存释放

  当函数执行完毕或代码块结束时，其对应的栈内存会自动弹出并释放，无需人工干预。

### 堆的作用

- 存储复杂引用数据

  为对象、数组、函数等大小不固定的数据结构提供动态内存空间。

- 支持数据共享

  多个变量可以指向堆内存中的同一个对象，实现数据的共享与引用传递。

- 动态内存分配

  允许程序在运行时根据需要动态申请和释放内存。

## 内存分配规则

JavaScript 中的数据类型决定了其内存的分配位置：

### 栈内存分配

基础数据类型（Primitive Types）的值直接存储在栈内存中。

- 包含类型

  `String`（字符串）、`Number`（数字）、`Boolean`（布尔值）、`Undefined`（未定义）、`Null`（空）、`Symbol`（符号）、`BigInt`（大整数）。

- 分配方式

  当声明一个基础类型变量时，引擎会在栈中为其分配一块固定大小的内存，并将值直接写入该内存。变量名直接指向这块栈内存。

- 特点

  数据大小固定，存取速度快，生命周期与执行上下文绑定。

### 堆内存分配

引用数据类型（Reference Types）的值存储在堆内存中，而变量在栈中存储的是指向堆内存的“地址指针”。

- 包含类型

  `Object`（对象）、`Array`（数组）、`Function`（函数）、`Date`（日期）、`RegExp`（正则表达式）等。

- 分配方式

  1. 当创建一个对象时，引擎在堆内存中开辟一块空间存储该对象的实际数据。
  2. 引擎在栈内存中为该变量分配空间，存储的是指向堆内存中该对象的地址（引用）。
  3. 变量通过栈中的地址间接访问堆中的实际数据。

- 特点

  数据大小不固定，存取速度相对较慢（需通过指针间接访问），生命周期由垃圾回收器管理。

## 对比总结

| 对比维度     | 栈（Stack）                                     | 堆（Heap）                                     |
| ------------ | ----------------------------------------------- | ---------------------------------------------- |
| **存储内容** | 基础数据类型值、函数调用上下文、局部变量。      | 引用数据类型（对象、数组、函数等）的实际数据。 |
| **内存结构** | 连续、有序的内存块。                            | 不连续、动态分配的内存块。                     |
| **存取速度** | 极快（直接访问）。                              | 较慢（需通过栈中的指针间接访问）。             |
| **内存大小** | 固定大小（由数据类型决定）。                    | 动态大小（根据对象实际内容分配）。             |
| **管理方式** | 引擎自动管理（随执行上下文进出自动分配/释放）。 | 垃圾回收器管理（定期扫描并回收不可达对象）。   |
| **数据访问** | 变量名直接对应值。                              | 变量名对应地址，地址指向实际值。               |

## 值传递与引用传递

理解栈与堆的区别，有助于理解 JavaScript 中数据传递的底层逻辑。

- 值传递（基础类型）

  当将一个基础类型变量赋值给另一个变量时，会在栈中复制一份完全独立的值。修改其中一个变量不会影响另一个。

- 引用传递（引用类型）

  当将一个引用类型变量赋值给另一个变量时，复制的只是栈中的“地址指针”。两个变量指向堆内存中的同一个对象。修改其中一个变量所指向的对象属性，另一个变量访问该属性时也会看到变化。

## 注意事项

- 避免不必要的深拷贝

  由于引用类型存储在堆中，频繁的深拷贝（Deep Clone）操作会消耗大量内存和 CPU 资源。应根据实际需求选择浅拷贝或深拷贝。

- 注意闭包中的内存占用

  闭包会持有外部函数作用域中的变量引用。如果这些变量是大型对象且长期驻留在堆内存中，可能导致内存泄漏。

- 及时解除引用

  对于不再需要的大型对象，应将其赋值为 `null`，主动切断栈中变量与堆中对象的引用链，帮助垃圾回收器及时释放内存。

- 利用工具分析内存

  使用浏览器开发者工具的 Memory 面板，可以查看堆内存的快照（Heap Snapshot），分析对象的分配情况和引用关系，排查内存泄漏问题。

# 垃圾回收

Garbage Collection，GC。

## 定义与本质

垃圾回收（Garbage Collection，简称 GC）是 JavaScript 引擎内置的一种自动内存管理机制。由于 JavaScript 在创建变量（对象、字符串、函数等）时会自动分配内存，并在不再需要时自动释放内存，这一过程完全由引擎在后台完成，开发者无需手动干预。其本质是通过特定的算法，定期找出那些“不再被使用”的变量，并回收它们所占用的内存空间。

## 核心作用

- 防止内存泄漏

  自动清理不再使用的内存，避免因开发者忘记释放内存而导致程序占用的内存持续增加，最终引发浏览器卡顿或崩溃。

- 降低开发复杂度

  将内存管理的负担从开发者身上转移给引擎，使开发者能更专注于业务逻辑的实现。

- 优化运行时性能

  现代垃圾回收器（如 V8 引擎的 Orinoco）采用分代回收、增量回收等高级策略，在保证内存安全的同时，尽可能减少回收过程对主线程的阻塞。

## 回收算法

### 引用计数法

JavaScript 中的“引用计数”（Reference Counting）是一种相对早期的内存管理算法。

该算法分为两个阶段：

1. 计数阶段（Counting）
   垃圾回收器会为内存中的每一个对象维护一个“引用计数器”。当有其他变量或对象引用该对象时，计数器加 1；当引用被解除（如变量被重新赋值、离开作用域或显式赋值为 `null`）时，计数器减 1。
2. 清除阶段（Sweeping）
   垃圾回收器会定期检查所有对象的引用计数器。凡是计数器为 0 的对象，都会被判定为不再被任何地方使用的垃圾内存，引擎会立即释放这些内存。

>**循环引用（Circular References）**
>
>引用计数法最大的问题在于无法处理循环引用。如果两个对象互相引用（例如对象 A 的属性指向对象 B，对象 B 的属性又指向对象 A），即使这两个对象已经不再被外部访问，它们的引用计数器也永远不会降为 0，从而导致内存泄漏。这也是现代 JavaScript 引擎（如 V8）放弃纯引用计数，转而采用“标记-清除”算法的主要原因。

### 标记清除法

JavaScript 引擎（如 Chrome 的 V8、Firefox 的 SpiderMonkey）主要采用 **“标记-清除”（Mark-and-Sweep）**算法来判断内存是否可用。

该算法分为两个阶段：

1. 标记阶段（Mark）

   垃圾回收器从“根对象”（Roots，如全局对象 `window`、当前执行的函数上下文等）出发，沿着引用链遍历所有可达的对象。凡是能被从根对象访问到的对象，都会被打上“活跃”标记。

2. 清除阶段（Sweep）

   遍历结束后，所有没有被标记为“活跃”的对象，都会被判定为不可达的垃圾内存，引擎会直接释放这些内存。

## 内存生命周期

理解垃圾回收，需要明确内存的三个生命周期阶段。

1. 内存分配

   在声明变量、创建对象或调用函数时，JavaScript 引擎会自动在堆（Heap）或栈（Stack）中分配内存。

2. 内存使用

   在代码中读写已分配的内存（如访问对象属性、调用函数）。

3. 内存释放

   当内存不再被需要时，由垃圾回收器自动释放。对于局部变量和基础类型，当它们离开作用域时，内存通常会立即被回收；对于复杂对象，则依赖垃圾回收器的定期扫描。

## 常见的内存泄漏场景

虽然垃圾回收是自动的，但开发者仍需注意避免人为造成的“内存泄漏”（即本应被回收的内存，因意外引用而无法被回收）。

- 意外的全局变量

  在函数内部未使用 `let`、`const` 或 `var` 声明的变量，会自动挂载到全局对象（`window`）上，导致其永远无法被回收。

- 被遗忘的定时器与回调

  `setInterval` 或事件监听器如果引用了外部对象，且未手动清除（`clearInterval` 或 `removeEventListener`），该对象及其引用的内存将无法被回收。

- 脱离 DOM 的引用

  将 DOM 节点存储在变量中，随后从文档中删除了该 DOM 节点，但变量依然持有对该节点的引用，导致该节点及其子树无法被回收。

- 闭包（Closure）

  内部函数引用了外部函数的变量，如果内部函数被外部持有，外部函数的变量对象也会一直保留在内存中，无法被垃圾回收。

## “使用”或干预垃圾回收

垃圾回收是自动运行的，但开发者可以通过以下方式配合或手动触发。

- 主动断开引用

  当确定某个大对象不再需要时，将其赋值为 `null`，主动切断引用链，帮助垃圾回收器在下一次扫描时更快地识别并回收该内存。

- 使用弱引用（WeakRef 与 FinalizationRegistry）

  ES2021 引入了 `WeakRef` 和 `FinalizationRegistry` API。`WeakRef` 允许创建对对象的弱引用（不阻止垃圾回收），而 `FinalizationRegistry` 允许注册一个回调函数，当对象被垃圾回收时触发。这为缓存、观察对象生命周期等高级场景提供了官方支持。

- 手动触发（仅限开发环境）

  在 Chrome DevTools 的 Memory 面板中，点击“Collect garbage”按钮（垃圾桶图标）可以手动触发一次完整的垃圾回收，用于性能分析和内存调试。

## 注意事项

- 遵循“最小权限”原则

  变量的作用域应尽可能小，避免不必要的全局变量或长生命周期变量。

- 及时清理副作用

  在组件卸载或页面销毁时，务必清理定时器、事件监听器和订阅。

- 慎用闭包

  虽然闭包非常强大，但过度使用会导致大量变量驻留内存。在不需要保留外部变量时，应及时解除引用。

- 利用工具监控

  定期使用浏览器的开发者工具（Performance Monitor、Memory Snapshot）监控内存使用情况，及时发现并修复潜在的内存泄漏。

# 引擎执行流程（以 V8 为例）

## 执行流程概述

现代 JavaScript 引擎（如 Chrome 的 V8、Firefox 的 SpiderMonkey）在执行 JavaScript 代码时，并非直接解释执行源代码，而是经历了一个从“文本”到“机器码”的复杂编译与优化过程。

整个流程可以概括为四个核心阶段：解析（Parsing）、编译（Compilation）、优化（Optimization）与执行（Execution）。

## 解析（Parsing）

解析阶段负责将人类可读的 JavaScript 源代码转换为计算机可理解的结构化数据。该阶段分为两个子步骤：

- 词法分析（Tokenizing/Lexing）

  将连续的源代码字符串拆解为一个个有意义的“词法单元”（Token）。例如，将 `let a = 1;` 拆解为 `let`、`a`、`=`、`1`、`;` 五个独立的 Token。

- 语法分析（Parsing）

  根据 JavaScript 的语法规则，将 Token 流组织成一棵抽象语法树（Abstract Syntax Tree，简称 AST）。AST 精确地描述了代码的逻辑结构，是后续编译的基础。

## 编译（Compilation）

编译阶段负责将抽象语法树（AST）转换为可执行的底层代码。现代引擎通常采用“即时编译”（Just-In-Time Compilation，简称 JIT）策略：

- 生成字节码（Bytecode）

  引擎首先将 AST 转换为一种与平台无关的中间表示形式——字节码。字节码比机器码更紧凑，生成速度更快，适合处理那些只执行一次或执行次数较少的“冷代码”。

- 生成机器码（Machine Code）

  对于频繁执行的“热代码”，引擎会直接将 AST 编译为当前 CPU 架构对应的原生机器码，以获得极致的执行性能。

## 优化（Optimization）

为了提升运行效率，现代引擎内置了高度复杂的优化编译器（如 V8 的 TurboFan）。优化器会在代码执行过程中持续监控，寻找优化机会：

- 内联缓存（Inline Caches）

  利用 JavaScript 对象属性访问的局部性原理，缓存对象属性的内存偏移量，避免每次都通过原型链查找。

- 隐藏类（Hidden Classes）

  引擎会为具有相同属性结构的对象创建内部的隐藏类，从而将动态属性的访问优化为类似静态语言的固定偏移量访问。

- 推测性优化（Speculative Optimization）

  引擎会根据历史执行数据“猜测”变量的类型（例如假设某个变量永远是整数），并基于此生成高度优化的机器码。如果运行时类型发生变化（去优化，Deoptimization），引擎会回退到未优化的字节码重新执行。

## 执行（Execution）

在执行阶段，JavaScript 引擎通过一系列运行时机制来管理代码的运行：

- 执行上下文（Execution Context）

  每当函数被调用或全局代码开始执行时，引擎都会创建一个新的执行上下文。这些上下文构成了“执行上下文栈”。

- 内存分配

  在执行过程中，引擎会根据数据类型，将基础类型数据分配到栈（Stack）内存，将引用类型数据分配到堆（Heap）内存。

- 垃圾回收（Garbage Collection）

  垃圾回收器会在后台异步运行，定期扫描堆内存，标记并清除那些不再被引用的对象，释放内存空间。

## 从源码到内存

整个执行流程将 JavaScript 的核心概念紧密地串联在一起：

- 作用域与 AST

  词法作用域的规则在解析阶段被写入 AST，并在编译阶段被转化为具体的内存寻址逻辑。

- 变量提升与执行上下文

  变量提升（Hoisting）本质上是引擎在创建执行上下文时，提前在内存中为 `var` 声明的变量分配了空间。

- 闭包与堆内存

  闭包之所以能“记住”外部变量，是因为内部函数对象被分配在堆内存中，并且其内部维护了一个指向外部执行上下文变量对象的引用，阻止了该变量对象被垃圾回收。

## 性能优化启示

- 避免频繁改变对象结构

  动态添加或删除对象属性会导致隐藏类失效，触发昂贵的去优化操作。应尽量在构造函数中一次性定义好所有属性。

- 减少不必要的动态特性

  过度使用 `eval()`、`with` 语句或动态属性访问（如 `obj[dynamicKey]`）会使引擎难以进行静态分析和优化，导致代码执行效率大幅下降。

- 编写对引擎友好的代码

  保持函数参数类型的一致性、避免在热循环中进行复杂的对象操作，都有助于引擎更好地进行推测性优化。

# 弱引用

## 介绍

`WeakRef` 和 `FinalizationRegistry` 是 ES2021（ES12）引入的高级内存管理 API。它们为开发者提供了直接干预和观察垃圾回收（GC）机制的能力，主要用于解决“需要持有对象引用，但不希望阻止该对象被垃圾回收”的高级场景。

## WeakRef

`WeakRef` 允许创建一个对对象的“**弱引用**”。弱引用不会阻止垃圾回收器回收该对象。

- 核心作用

  在不影响对象正常生命周期（即不阻止 GC）的前提下，保留对对象的访问能力。

- 使用格式

  ```javascript
  const weakRef = new WeakRef(targetObject)
  // targetObject：必需参数，想要创建弱引用的目标对象（必须是对象，不能是原始值）。
  ```

- 访问对象

  通过 `.deref()` 方法获取目标对象。如果对象已被 GC 回收，则返回 `undefined`。

  ```javascript
  const obj = weakRef.deref();
  if (obj) {
      // 对象依然存在，可以安全访问
      console.log(obj.name);
  } else {
      // 对象已被回收
      console.log('对象已不存在');
  }
  ```

- 典型应用场景

  - 大型对象缓存

    在缓存系统中存储大型对象（如 DOM 节点、大型数据集）。当内存紧张时，GC 可以自动回收这些缓存对象，而不会因为缓存 Map 的强引用导致内存泄漏。

  - 观察者模式

    在事件监听器中持有对目标的弱引用，避免监听器阻止目标对象被回收。

## FinalizationRegistry

`FinalizationRegistry` 允许注册一个回调函数，当注册的对象被垃圾回收时，该回调会被触发。

- 核心作用

  在对象生命周期结束时，执行清理外部资源（如文件句柄、网络连接、WebAssembly 内存等）的逻辑。

- 使用格式

  ```javascript
  const registry = new FinalizationRegistry(callback)
  // callback：必需参数，一个回调函数。当注册的对象被 GC 回收时，该函数会被调用，并接收注册时传入的 heldValue 作为参数。
  ```

- 注册对象

  ```javascript
  registry.register(target, heldValue, unregisterToken)
  // target：必需参数，想要监控的目标对象。
  // heldValue：必需参数，一个任意值（不能是 target 本身），当 target 被回收时，该值会作为参数传递给回调函数。
  // unregisterToken：可选参数，一个令牌。用于在 target 被回收前主动取消注册。
  ```

- 典型应用场景

  - 清理非 JS 资源

    当 JS 对象被回收时，自动释放与之关联的 C++ 层资源或底层系统资源。

  - 内存使用监控

    在开发或调试阶段，统计对象被回收的频率和时机。

## 注意事项

- 非确定性

  垃圾回收的时机、频率以及是否执行，完全由 JavaScript 引擎决定。`FinalizationRegistry` 的回调**不保证**何时执行，甚至**不保证**一定会执行（例如在浏览器标签页关闭时）。

- 禁止依赖

  绝不能将关键的业务逻辑（如保存用户数据、关闭数据库连接）依赖于 `FinalizationRegistry` 的回调。它仅应作为非关键资源清理的“兜底”机制。

- 性能开销

  `WeakRef` 和 `FinalizationRegistry` 会增加引擎的运行时负担。仅在确实需要优化内存或管理外部资源时使用，避免滥用。

- 同一事件循环保护

  在当前 JavaScript 任务（Job）结束前，刚创建的 `WeakRef` 的目标对象不会被回收。这保证了代码在执行期间能稳定地访问到对象。

## 最佳实践

- 优先使用标准机制

  对于资源清理，优先使用 `try...finally` 或显式的 `dispose()` 方法。`FinalizationRegistry` 仅作为辅助的清理手段。

- 避免循环引用

  `WeakRef` 无法解决循环引用导致的内存泄漏。仍需合理设计对象的生命周期和引用关系。

- 结合使用

  在高级缓存场景中，通常将 `WeakRef` 与 `FinalizationRegistry` 结合使用。`WeakRef` 用于缓存对象，`FinalizationRegistry` 用于在对象被回收时清理缓存 Map 中对应的无效条目。

# 函数参数

## 定义与本质

在 JavaScript 中，函数的动态参数（Dynamic Parameters）是指函数在定义时无法确定参数的个数，而是在调用时根据实际情况动态传入任意数量的参数。其本质是 JavaScript 函数具备的一种灵活接收和处理不定数量实参的机制。

## 核心作用

- 提升函数灵活性

  允许编写能够处理任意数量输入的通用函数（如求和、求平均值、字符串拼接等）。

- 简化函数签名

  避免为了接收多个参数而定义冗长的形参列表。

- 支持高阶函数与工具函数

  在函数式编程或封装通用工具时，方便将参数透传或聚合处理。

## 实现方式与使用规则

JavaScript 提供了两种主要的机制来实现动态参数：**剩余参数（Rest Parameters）**和 **arguments 对象**。

### 剩余参数

剩余参数（Rest Parameters）是 ES6 引入的语法，使用展开运算符（`...`）加上一个变量名，将函数调用时传入的“多余”实参收集为一个真正的数组。

- 语法格式

  ```javascript
  function functionName(固定参数1, 固定参数2, ...restParam) {
      // restParam 是一个真正的数组，包含了所有剩余的传入参数
  }
  ```

- 核心规则

  - 必须放在最后

    剩余参数只能作为函数参数列表中的最后一个参数。

  - 只能有一个

    一个函数的参数列表中，最多只能包含一个剩余参数。

  - 收集的是“剩余”的实参

    它只会收集那些没有被前面的形参“认领”的参数。

- 优势

  - 得到的是真正的 `Array` 实例，可以直接使用 `map`、`filter`、`reduce` 等数组方法。
  - 支持箭头函数。
  - 语义更清晰，代码更简洁。

### arguments 对象

`arguments` 是一个存在于所有非箭头函数执行上下文中的特殊对象（类数组），用于保存并代表实际传递给该函数的所有参数。

- 核心特性

  - 类数组结构

    具有 `length` 属性，且可以通过数字索引访问，但不具备数组的内置方法（如 `forEach`）。

  - 自动创建

    只要是非箭头函数，在函数调用时都会自动创建。

  - 包含所有实参

    无论函数定义时是否声明了对应的形参，`arguments` 都会包含所有传入的参数。

- 局限性

  - 在箭头函数中不可用。
  - 需要额外转换才能使用数组方法。
  - 在非严格模式（`use strict`）下，与形参存在动态绑定关系，容易引发难以追踪的 Bug。

## 两种方法对比

| 对比维度           | 剩余参数（...args）                | arguments 对象                           |
| ------------------ | ---------------------------------- | ---------------------------------------- |
| **数据类型**       | 真正的数组（可直接用数组方法）     | 类数组对象（需转换为数组才能用数组方法） |
| **包含范围**       | 仅包含“未被前面形参匹配的剩余实参” | 包含所有传入的实参                       |
| **箭头函数支持**   | 支持                               | 不支持（箭头函数没有 arguments）         |
| **现代开发推荐度** | 高（ES6+ 标准写法）                | 低（仅用于兼容旧代码或特殊场景）         |

## 典型应用场景示例

### 数学计算工具函数

```javascript
// 使用剩余参数计算任意数量的平均值
function calculateAverage(...numbers) {
    if (numbers.length === 0) return 0;
    const sum = numbers.reduce((acc, cur) => acc + cur, 0);
    return sum / numbers.length;
}
```

### 分离固定参数与动态配置

```javascript
// 第一个参数是固定的日志级别，后续的参数全部打包为消息数组
function log(level, ...messages) {
    console.log(`[${level.toUpperCase()}]:`, messages.join(' '));
}
```

### 高阶函数与参数透传

```javascript
// 包装任意函数，在执行前后打印日志
function withLogging(fn) {
    return function (...args) {
        console.log(`开始执行: ${fn.name}`);
        const result = fn(...args); // 透传所有参数
        console.log(`执行完毕: ${fn.name}`);
        return result;
    };
}
```

## 注意事项

- 优先使用剩余参数

  现代 JavaScript 开发中，应全面使用剩余参数替代 `arguments` 对象。

- 注意剩余参数的位置

  剩余参数必须放在参数列表的最后，否则会导致语法错误。

- 避免与 arguments 混用

  在使用了剩余参数的函数中，虽然 `arguments` 依然存在，但不推荐再使用，以免逻辑混乱。

- 边界情况处理

  当调用函数时没有传入额外参数，剩余参数会是一个空数组 `[]`，而不是 `undefined`，在使用数组方法（如 `reduce`）时需注意初始值的设置。

# 剩余参数（Rest）与展开语法（Spread）

虽然剩余参数与展开语法在书写形式上完全一致（均为 `...`），但两者的核心作用截然相反。剩余参数用于在函数定义时“收集”参数，而展开语法用于在函数调用或数据结构构建时“拆解”数据。

## 核心作用对比

| 对比维度     | 剩余参数（Rest Parameters）                           | 展开语法（Spread Syntax）                              |
| ------------ | ----------------------------------------------------- | ------------------------------------------------------ |
| **核心动作** | **收集（Collect）**：将多个零散的参数打包成一个数组。 | **展开（Expand）**：将一个数组或对象拆解成零散的个体。 |
| **使用位置** | **函数定义**时的参数列表中。                          | **函数调用**、数组字面量、对象字面量中。               |
| **数据流向** | 多个独立参数 → 一个数组。                             | 一个数组/对象 → 多个独立元素/属性。                    |
| **语法示例** | `function func(...args) {}`                           | `func(...arr)` 或 `[...arr]` 或 `{...obj}`             |

## 应用场景对比

| 场景分类     | 剩余参数（Rest）用法                                         | 展开语法（Spread）用法                                       |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **函数操作** | 接收任意数量的实参并打包为数组。 `function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }` | 将数组拆解为独立的实参传递给函数。 `const values = [1, 2, 3];<br />console.log(Math.max(...values)); // 输出: 3` |
| **数组操作** | 仅用于函数参数收集，不直接用于数组赋值。                     | 合并数组或创建数组的浅拷贝。 `const arr1 = [1, 2];<br>const arr2 = [3, 4];<br>const merged = [...arr1, ...arr2]; // [1, 2, 3, 4]` |
| **对象操作** | 不支持用于对象属性的收集。                                   | 合并对象或创建对象的浅拷贝（ES2018+）。 `const obj1 = { a: 1 };<br>const obj2 = { b: 2 };<br>const merged = { ...obj1, ...obj2 }; // { a: 1, b: 2 }` |
| **解构赋值** | 收集解构后剩余的属性或元素。 `const [first, ...rest] = [1, 2, 3]; // rest = [2, 3]` | 不支持在解构赋值的左侧使用展开语法。                         |

## 注意事项

- 剩余参数的位置限制

  在函数定义中，剩余参数必须放在参数列表的**最后一个位置**，且一个函数只能有一个剩余参数。

- 展开语法的灵活性

  展开语法可以在数组或对象中的任意位置使用（如 `[...arr, 4, 5]` 或 `{ a: 1, ...obj }`），且可以多次使用。

- 浅拷贝特性

  使用展开语法复制对象或数组时，仅进行浅拷贝。如果原数据中包含嵌套的引用类型，复制后的新数据仍会指向同一个嵌套对象。

- 空值处理

  当对 `null` 或 `undefined` 使用展开语法时，在数组中会被忽略（视为空），但在对象中会被忽略（不产生任何属性）。

# 箭头函数

## 定义与本质

箭头函数是 ES6（ECMAScript 2015）引入的一种定义函数的简写语法，使用箭头符号（`=>`）来替代传统的 `function` 关键字。其本质是一种**匿名函数表达式**，它不仅在语法上更加简洁，更重要的是改变了 `this` 关键字的绑定机制，使其遵循词法作用域（Lexical Scope）。

## 核心作用

- 简化函数语法

  大幅减少函数定义的样板代码，使代码更加紧凑和易读。

- 解决 `this` 指向问题

  箭头函数没有自己的 `this`，它会捕获其定义时所在外层作用域的 `this` 值。这彻底解决了传统函数在回调、定时器或事件处理器中 `this` 指向丢失或意外改变的问题。

- 提升函数式编程体验

  在数组的高阶方法（如 `map`、`filter`、`reduce`）中，箭头函数能让回调函数的逻辑更加直观。

## 语法格式

箭头函数的语法非常灵活，根据参数数量和函数体的复杂度，可以进行不同程度的简化。

### 基础语法结构

```javascript
(参数1, 参数2, ...参数N) => { 函数体 }
```

### 语法简化规则

- 无参数：必须使用空括号。

  ```javascript
  const sayHi = () => console.log('Hi!');
  ```

- 单个参数：可以省略参数外层的括号。

  ```javascript
  const double = x => x * 2;
  ```

- 多个参数：必须使用括号包裹参数列表。

  ```javascript
  const add = (a, b) => a + b;
  ```

- 单行函数体（隐式返回）：如果函数体只有一条语句，可以省略花括号 `{}` 和 `return` 关键字，表达式的结果会自动返回。

  ```javascript
  const sum = (a, b) => a + b; // 等同于 (a, b) => { return a + b; }
  ```

- 多行函数体：必须使用花括号 `{}` 包裹代码块，并且需要显式使用 `return` 语句返回值。

  ```javascript
  const calculate = (a, b) => {
      const result = a + b;
      return result;
  };
  ```

- 返回对象字面量：如果单行函数体需要直接返回一个对象，必须用圆括号 `()` 将对象包裹起来，以避免与代码块的 `{}` 产生语法冲突。

  ```javascript
  const fn = (name, age) => ({ name: name, age: age });
  const obj = fn("张三", 18);
  console.log(obj.name); 	// 张三
  console.log(obj.age); 	// 18
  ```

## 类型注解

### 使用 `@param` 和 `@returns`

```javascript
/**
 * 创建一个用户对象
 * @param {string} name - 用户的名字
 * @param {number} age - 用户的年龄
 * @returns {{ name: string, age: number }}
 */
const fn = (name, age) => ({ name: name, age: age });
```

**注意返回值写法**：`{{ name: string, age: number }}`，外层的 `{}` 表示这是一个对象类型，里面的 `{}` 描述对象的具体属性结构。

### 使用 `@type` 类型定义

如果不想写多行注释，可以直接在变量上方用 `@type` 描述整个函数类型：

```javascript
/** @type {(name: string, age: number) => { name: string, age: number }} */
const fn = (name, age) => ({ name: name, age: age });
```

### 同一个对象结构

如果你的对象结构比较复杂，可以用 `@typedef` 先定义结构，再引用，代码复用性更强：

```javascript
/**
 * @typedef {Object} User
 * @property {string} name - 用户名
 * @property {number} age - 用户年龄
 */

/**
 * 创建用户
 * @param {string} name
 * @param {number} age
 * @returns {User}
 */
const fn = (name, age) => ({ name: name, age: age });
```

### ES6 简写不影响类型

即使用了 `({ name, age })` 这种简写，JSDoc 写法完全一样：
```javascript
/**
 * @param {string} name
 * @param {number} age
 * @returns {{ name: string, age: number }}
 */
const fn = (name, age) => ({ name, age });
```

## 与传统函数的区别

| 对比维度               | 传统函数（Function）                                        | 箭头函数（Arrow Function）                                   |
| ---------------------- | ----------------------------------------------------------- | ------------------------------------------------------------ |
| `this` 绑定            | 动态绑定。<br />`this` 的值取决于函数**被调用时**的上下文。 | 词法绑定。<br />`this` 的值取决于函数**定义时**的外层作用域，<br />且一旦绑定不可改变。 |
| `arguments` 对象       | 拥有自己的 `arguments` 对象，<br />包含所有传入的参数。     | 没有自己的 `arguments` 对象。<br />需使用剩余参数（`...args`）替代。 |
| 构造函数               | 可以作为构造函数，<br />使用 `new` 关键字创建实例。         | 不能作为构造函数。<br />使用 `new` 调用会抛出 `TypeError` 错误。 |
| `prototype` 属性       | 拥有 `prototype` 属性。                                     | 没有 `prototype` 属性。                                      |
| `super` / `new.target` | 支持 `super` 和 `new.target` 关键字。                       | 不支持 `super` 和 `new.target` 关键字。                      |
| 生成器函数             | 可以使用 `function*` 语法定义为生成器。                     | 不能用作生成器函数，<br />函数体内不能使用 `yield` 关键字。  |

## 适用场景

- 适用场景

  - 数组的高阶方法回调（`map`，`filter`，`reduce`，`sort` 等）。
  - Promise 链式调用（`.then()`，`.catch()`）。
  - 事件监听器（`addEventListener`）和定时器（`setTimeout`，`setInterval`）。
  - 任何不需要独立 `this` 上下文的简短回调函数。

- 不适用场景（限制）

  - 对象方法

    在对象字面量中定义方法时，如果使用箭头函数，`this` 会指向外层作用域（通常是 `window` 或 `global`），而不是对象本身。

  - 原型方法

    在原型上定义方法时，同样因为 `this` 指向问题，应使用传统函数。

  - 需要动态 `this` 的场景

    如构造函数、需要利用 `call()`、`apply()`、`bind()` 动态改变 `this` 指向的函数。

## 注意事项

- 优先使用箭头函数

  在处理回调函数和不需要独立 `this` 的逻辑片段时，优先使用箭头函数以提升代码可读性。

- 避免在对象/类方法中使用

  除非明确需要捕获外层的 `this`（如在 React 类组件中自动绑定实例方法），否则不要在对象字面量或类的原型上直接使用箭头函数定义方法。

- 注意隐式返回的陷阱

  在单行箭头函数中，如果不小心写成了多条语句但没有加花括号，会导致逻辑错误。当函数体变复杂时，应及时补充花括号和 `return`。

- 利用剩余参数

  由于箭头函数没有 `arguments` 对象，在需要处理动态参数时，应养成使用剩余参数（`...args`）的习惯。
