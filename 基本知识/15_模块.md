# 模块介绍

## 概念

模块（Module）是指一个包含 JavaScript 代码的文件。每个模块拥有独立的作用域，在模块顶层声明的变量、函数、类等对外不可见，除非通过显式导出（`export`）将其暴露。模块是代码组织和封装的基本单元。

ES Module（ES6 模块）是 ECMAScript 2015 在语言标准层面正式引入的模块方案，通过 `import` 和 `export` 关键字实现。所有现代浏览器均已原生支持模块功能。

模块始终运行在严格模式（Strict Mode）下。一个文件是否被视为模块，取决于其是否包含顶层的 `import` 声明、`export` 声明或顶层 `await`。不包含上述声明的文件被视为普通脚本（Script），其内容处于全局作用域中。

## 作用

模块机制为 JavaScript 程序带来了以下核心价值：

1. 作用域隔离与封装：模块拥有独立的作用域，避免了变量污染全局命名空间。模块的内部实现细节对外部隐藏，仅通过导出的接口对外交互。
2. 代码复用：模块可被多次导入，便于在不同项目中复用功能。
3. 可维护性：模块的独立性降低了代码耦合度，每个模块可独立更新和改进。
4. 依赖管理：通过 `import` 语句显式声明模块间的依赖关系，使依赖结构清晰可查。
5. 按需加载：支持动态导入（`import()`），可在运行时按需加载模块。

# 基本语法

## 导出

`export` 声明用于从模块中导出值。导出的值可通过 `import` 声明或动态导入被其他程序使用。每个模块可拥有两种类型的导出：命名导出（Named Export）和默认导出（Default Export）。一个模块可包含多个命名导出，但只能有一个默认导出。

### 命名导出

在声明时直接导出：

```javascript
export let name1, name2;                // 导出变量
export const name1 = 1, name2 = 2;      // 导出常量
export function functionName() { ... }  // 导出函数
export class ClassName { ... }          // 导出类
```

先声明后统一导出：

```javascript
const myVar = 42;
function myFunc() { ... }
export { myVar, myFunc };
```

使用 `as` 重命名导出：

```javascript
export { myVar as newName };
```

### 默认导出

每个模块只能有一个默认导出：

```javascript
export default expression;              // 导出任意表达式
export default function() { ... }       // 导出匿名函数
export default function name() { ... }  // 导出具名函数
export default class { ... }            // 导出匿名类
```

### 重导出

Re-exporting / Aggregating，转发其他模块的导出：

```javascript
export * from "module-name";            // 导出目标模块的所有命名导出
export * as name1 from "module-name";   // 导出为命名空间
export { name1, name2 } from "module-name"; // 选择性转发
export { name1 as newName } from "module-name"; // 重命名后转发
```

> 注意：`export * from "module-name"` 不会转发目标模块的默认导出。

## 导入

`import` 声明用于导入其他模块导出的只读实时绑定（Live Bindings）。导入的绑定是只读的，不能被重新赋值。

### 导入命名导出

```javascript
import { name1 } from "module-name";            // 导入单个命名导出
import { name1, name2 } from "module-name";     // 导入多个
import { name1 as alias } from "module-name";   // 重命名导入
```

### 导入默认导出

```javascript
import defaultExport from "module-name";        // 默认导出可使用任意名称
```

### 命名空间导入

```javascript
import * as namespace from "module-name";       // 将所有命名导出聚合为对象
```

### 仅副作用导入

执行模块代码，不导入任何绑定。

```javascript
import "module-name";
```

### 混合导入

默认导出与命名导出同时导入。

```javascript
import defaultExport, { name1, name2 } from "module-name";
import defaultExport, * as namespace from "module-name";
```

## 重命名导入与导出

使用 `as` 关键字可为导入或导出的成员重命名，以解决命名冲突问题：

```javascript
// 重命名导入
import { draw as drawCircle } from "./circle.js";
import { draw as drawSquare } from "./square.js";

// 重命名导出
export { myFunction as function1 };
```

## 模块对象

使用 `import * as` 可将一个模块的所有导出聚合为一个对象（Module Object），有效避免命名冲突：

```javascript
import * as Circle from "./circle.js";
import * as Square from "./square.js";

Circle.draw();  // 调用 circle 模块的 draw
Square.draw();  // 调用 square 模块的 draw
```

# 使用方式

## 在浏览器中使用

在 HTML 中，通过 `<script>` 标签的 `type="module"` 属性加载模块脚本：

```html
<script type="module" src="main.js"></script>
```

模块脚本默认具有延迟执行（Defer）行为，不会阻塞页面渲染。模块导入路径必须使用完整的相对路径（以 `./` 或 `../` 开头）、绝对路径（以 `/` 开头）或完整 URL。

**注意事项**

1. 模块脚本必须通过 HTTP 或 HTTPS 协议提供服务，不支持 `file://` 协议。
2. 模块脚本自动处于严格模式。
3. 内联模块脚本同样支持 `import` 和 `export` 语法。

## 动态导入

`import()` 是一个类似函数的表达式，允许异步和动态地加载模块。与静态 `import` 声明不同，动态导入仅在需要时被评估，支持条件加载和按需加载。

```javascript
// 基本用法
import("./module.js")
    .then(module => {
        module.someFunction();
    })
    .catch(err => {
        console.error("模块加载失败", err);
    });

// 结合 async/await
const module = await import("./module.js");

// 条件加载
if (userIsLoggedIn) {
    const dashboard = await import("./dashboard.js");
    dashboard.render();
}
```

动态导入返回一个 Promise，在模块成功加载和评估后兑现为一个**模块命名空间对**象。动态导入不需要 `type="module"` 脚本。

常见使用场景包括：按需加载以提升性能、条件加载、懒加载路由模块等。

# TypeScript 中的模块

TypeScript 遵循 ECMAScript 模块规范。任何包含顶层 `import` 或 `export` 声明的文件被视为模块。

## 类型导入与导出

```typescript
// 仅导入类型（编译后完全擦除）
import type { SomeType } from "./module";

// 混合导入（使用 type 关键字标记类型）
import { f, type SomeInterface } from "./module";

// 仅导出类型
export type { SomeType };
export type { AnInterface } from "./foo";
```

## 内联类型导入

```typescript
// 在类型位置直接导入类型
type Options = import("fs").WriteFileOptions;
```

## 将非模块文件视为模块

若文件没有任何 `import` 或 `export`，但需被视为模块，可添加空导出语句：

```typescript
export {};
```

# 模块说明符解析

模块说明符（Module Specifier）的解析由宿主环境决定。在浏览器中，说明符被解析为相对于当前模块 URL 的 URL。常见的模块说明符形式包括：

1. 相对路径：`./module.js`、`../lib/module.js`
2. 绝对路径：`/modules/module.js`
3. 完整 URL：`https://example.com/module.js`

裸模块说明符（如 `import axios from "axios"`）在浏览器中不被原生支持，需要通过打包工具或 `importmap` 进行映射。
