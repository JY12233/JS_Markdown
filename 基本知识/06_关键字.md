# delete

在 JavaScript 中，`delete` 是一个一元运算符，专门用于删除对象的属性。当属性被成功删除后，该属性将不再存在于对象中。

## 语法格式

```javascript
delete object.property;        // 点表示法：删除对象上指定的属性
delete object['property'];     // 括号表示法：通过字符串键名删除对象上的属性
delete object[index];          // 数组索引：删除数组中指定索引的元素（注意：不会改变数组长度，该位置变为 empty）
```

## 语法成分详解

| 语法成分             | 作用与说明                               | 数据类型要求                                                 |
| -------------------- | ---------------------------------------- | ------------------------------------------------------------ |
| `object`             | 指定要操作的宿主对象。                   | 必须为对象（`Object`）或数组（`Array`）。                    |
| `.`                  | 点操作符，用于访问对象的属性。           | 右侧必须是合法的标识符<br />（不能包含特殊字符或以数字开头）。 |
| `[...]`              | 括号操作符，用于通过表达式动态访问属性。 | 括号内的表达式求值结果会被转换为字符串作为键名。             |
| `property` / `index` | 要删除的属性名或数组索引。               | 字符串、数字或 Symbol。                                      |

## 变体与修饰符说明

`delete` 关键字本身没有修饰符或变体，但其执行结果受属性描述符（Property Descriptor）和严格模式的严格限制。

| 属性特征 / 运行环境         | 行为影响与说明                                               |
| --------------------------- | ------------------------------------------------------------ |
| `configurable: true`        | 属性可配置。<br />`delete` 操作会成功删除该属性，并返回 `true`。 |
| `configurable: false`       | 属性不可配置（如通过 `Object.defineProperty` 锁定的属性）。<br />`delete` 操作无效，属性保留。 |
| 严格模式 （`'use strict'`） | 如果尝试删除不可配置的属性，或传入非引用<br />（如 `delete x`），会直接抛出 `TypeError` 异常。 |
| 非严格模式                  | 如果尝试删除不可配置的属性，操作静默失败，返回 `false`，不会抛出异常。 |
| 直接删除变量                | 使用 `delete` 删除直接声明的变量（如 `var`、`let`、`const` 声明的变量）是无效的。<br />在严格模式下会报错。 |

## 常见配套语法与行为影响

| 配套语法 / 场景            | 行为影响与说明                                               |
| -------------------------- | ------------------------------------------------------------ |
| `in` 操作符                | 常与 `delete` 搭配用于验证。`delete` 后使用 `'prop' in obj` 会返回 `false`。 |
| `hasOwnProperty()`         | 常与 `delete` 搭配用于验证。<br />`delete` 后调用 `obj.hasOwnProperty('prop')` 会返回 `false`。 |
| `Object.keys()`            | `delete` 操作后，被删除的属性不会出现在 `Object.keys()` 返回的数组中。 |
| `Array.prototype.splice()` | 当需要删除数组元素且**不希望留下空位**时，应使用 `splice()` 代替 `delete`。<br />`splice` 会改变数组长度并重新排列后续元素。 |
| `undefined` 赋值           | 如果只是想清除属性的值但**保留该属性键**，<br />应使用 `obj.prop = undefined` 代替 `delete`。 |

# in

在 JavaScript 中，`in` 是一个二元运算符，专门用于检查指定的属性名是否存在于某个对象或其原型链中。

## 语法格式与使用方式

```javascript
prop in object; 
// prop: 要检查的属性名或数组索引（通常为字符串或 Symbol，非 Symbol 类型会自动转为字符串）
// object: 要检查的目标对象（或数组）
```

## 语法成分与变体详解

| 语法成分 / 变体 | 作用与说明                                                   | 数据类型要求                                                 | 可选写法与变体                                               |
| --------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `prop`          | 指定要检查的属性名或索引。                                   | 字符串、Symbol 或数字（数字会自动转为字符串）。              | 无                                                           |
| `object`        | 指定要检查的目标对象。                                       | 必须是对象或数组。对 `null` 或 `undefined` 使用会抛出 `TypeError`。 | 无                                                           |
| 原型链检查      | `in` 会沿着对象的原型链向上查找，只要属性在对象自身或原型链上存在，就返回 `true`。 | -                                                            | 若只想检查对象自身的属性（不查原型链），需使用 `hasOwnProperty()` 或 `Object.hasOwn()`。 |

## 常见配套语法与行为影响

| 配套语法 / 场景    | 行为影响与说明                                               |
| ------------------ | ------------------------------------------------------------ |
| `delete` 操作符    | 使用 `delete` 删除属性后，`in` 运算符对该属性会返回 `false`。 |
| `undefined` 赋值   | 若仅将属性值设为 `undefined`（未删除），`in` 仍会返回 `true`。 |
| `for...in` 循环    | 用于遍历对象的所有可枚举属性（包括继承的）。<br />不推荐用 `for...in` 遍历数组，因为它也会遍历非数字键。 |
| `hasOwnProperty()` | 仅检查属性是否为对象自身的属性，不检查原型链。               |
| 数组索引检查       | 对数组使用时，`in` 检查的是索引（键名）是否存在，而不是值是否存在。<br />空位（empty slots）会返回 `false`。 |

## 代码示例

```javascript
// 对象属性检查
const car = { make: 'Toyota', year: 2022 };
console.log('make' in car);        // true（自有属性）
console.log('toString' in car);    // true（继承自 Object.prototype）
console.log('color' in car);       // false（不存在）

// 数组索引检查
const fruits = ['apple', 'banana'];
console.log(0 in fruits);          // true（索引 0 存在）
console.log('apple' in fruits);    // false（检查的是键名，不是值）
console.log(5 in fruits);          // false（索引 5 不存在）
```

# as

在 JavaScript 中，`as` 关键字主要用于 ES6 模块化（Module）中的重命名操作。此外，在 TypeScript 中，`as` 被用于类型断言（Type Assertion）。

## 语法格式

`as` 关键字在 JavaScript 模块化中主要有三种使用场景：导入重命名、导出重命名以及命名空间导入。

```javascript
// 1. 导入重命名：解决命名冲突或简化长名称
import { originalName as newName } from './module.js';
// originalName：模块对外暴露的原始接口名称。
// newName：在当前文件中使用的本地别名。

// 2. 导出重命名：对外暴露不同的接口名称，隐藏内部变量名
export { internalName as externalName };
// internalName：模块内部的原始变量或函数名。
// externalName：对外暴露的别名，外部模块需使用此名称导入。

// 3. 命名空间导入：将模块的所有导出内容聚合为一个对象
import * as namespaceName from './module.js';
// namespaceName：自定义的命名空间对象名称，通过点语法访问其内部的导出成员。
```

## 语法成分详解

| 语法成分                   | 作用描述                       | 数据类型要求                           | 可选写法或说明                                 |
| -------------------------- | ------------------------------ | -------------------------------------- | ---------------------------------------------- |
| `originalName`             | 指定要导入或导出的原始标识符。 | 必须是目标模块中已存在的导出成员名称。 | 无。                                           |
| `newName` / `externalName` | 指定在导入或导出时使用的别名。 | 合法的 JavaScript 标识符。             | 若不需要重命名，可直接省略 `as newName` 部分。 |
| `namespaceName`            | 指定命名空间对象的名称。       | 合法的 JavaScript 标识符。             | 必须配合 `import *` 语法使用。                 |

**TypeScript 变体说明：**

在 TypeScript 中，`as` 还用于类型断言，语法格式为 `value as Type`。它告诉编译器将 `value` 视为 `Type` 类型，但不进行运行时的实际转换。例如：`const canvas = document.getElementById('main') as HTMLCanvasElement;`。

## 常见配套语法与行为影响

| 配套语法              | 行为影响                       | 典型使用场景                                                 |
| --------------------- | ------------------------------ | ------------------------------------------------------------ |
| `import { ... } from` | 配合 `as` 实现导入时的重命名。 | 导入多个模块时存在同名成员，或原名称过长。                   |
| `export { ... }`      | 配合 `as` 实现导出时的重命名。 | 模块内部变量名与对外接口名不一致，或避免污染全局命名空间。   |
| `import *`            | 配合 `as` 实现整体导入。       | 需要调用模块中的多个方法，且希望以对象属性的方式访问（如 `Tools.format()`）。 |
| `export default as`   | 将默认导出重命名为命名导出。   | 语法：`export { default as ComponentName }`，常用于统一组件库的导出接口。 |

## 代码示例

```javascript
// utils.js 模块
const formatPrice = (price) => `¥${price}`;
const formatDate = (date) => date.toLocaleDateString();
export { formatPrice, formatDate };

// main.js 模块
// 导入时重命名，避免与当前作用域的同名变量冲突
import { formatPrice as priceFormatter } from './utils.js';

// 命名空间导入，将所有工具方法聚合到 utils 对象下
import * as utils from './utils.js';

console.log(priceFormatter(100)); // 输出: ¥100
console.log(utils.formatDate(new Date())); // 输出: 当前日期的本地化字符串
```

# new

`new` 是 JavaScript 中用于创建对象实例的关键字。当配合构造函数或类（Class）使用时，它会触发一套严谨的对象创建协议，将普通函数转化为“造对象的模具”。

## 语法格式

`new` 关键字的执行过程严格遵循以下四个步骤：

```javascript
const instance = new Constructor(arg1, arg2);
// new：触发构造函数机制的关键字，启动对象创建流程。
// Constructor：构造函数或类的名称，定义了对象的结构和初始化逻辑。
// arg1, arg2：传递给构造函数的参数，用于初始化实例的属性。
// instance：最终创建并返回的对象实例。
```

当执行 `new Constructor(...)` 时，JavaScript 引擎会在后台自动执行以下四个步骤：

1. 创建空对象

   在内存中创建一个全新的空对象（`{}`）。

2. 建立原型链接

   将这个新对象的原型（`__proto__`）指向构造函数的 `prototype` 属性，从而建立原型链。

3. 绑定 this 并执行

   将构造函数内部的 `this` 绑定到这个新对象上，并执行函数体内的代码（通常为 `this` 添加属性和方法）。

4. 返回对象

   如果构造函数没有显式返回一个对象，则自动返回这个新创建的对象；如果显式返回了一个非原始值（对象），则返回该对象。

## 语法成分详解

| 语法成分      | 作用描述                         | 数据类型要求与规则                                           |
| ------------- | -------------------------------- | ------------------------------------------------------------ |
| Constructor   | 指定对象实例类型的类或函数。     | 必须是函数或 ES6 Class。箭头函数不可作为构造函数。           |
| arg1, arg2... | 用于被构造函数调用的值列表。     | 任意数据类型。若无参数，括号可省略（如 `new Date`）。        |
| this 关键字   | 指向当前正在被创建的新对象实例。 | 仅在配合 `new` 调用时有效；<br />直接调用会导致 `this` 指向全局对象或 `undefined`。 |
| 返回值        | 决定 `new` 表达式的最终结果。    | 默认隐式返回新对象。<br />若显式返回对象，则覆盖默认对象；若返回原始值，则被忽略。 |

## 变体与修饰符

| 变体/修饰符 | 说明                                                         |
| ----------- | ------------------------------------------------------------ |
| ES6 Class   | `class` 语法是构造函数的语法糖。<br />类只能通过 `new` 实例化，直接调用类名会抛出 `TypeError`。 |
| new.target  | 在函数内部使用，用于检测函数是否通过 `new` 调用。<br />若通过 `new` 调用，`new.target` 指向构造函数本身；否则为 `undefined`。 |

## 配套语法

| 配套语法     | 行为影响                                                     |
| ------------ | ------------------------------------------------------------ |
| `instanceof` | 用于检查一个对象是否是特定构造函数的实例（例如 `obj instanceof Person`）。 |
| `prototype`  | 构造函数的 `prototype` 属性定义了由该函数创建的所有对象所共享的属性和方法。 |
| `super`      | 在子类构造函数中，必须在使用 `this` 之前调用 `super()`，以执行父类构造函数的初始化逻辑。 |

## 代码示例

```javascript
// 定义一个 Car 构造函数
function Car(brand, color) {
  this.brand = brand; // 初始化品牌属性。
  this.color = color; // 初始化颜色属性。
}

// 将共享方法挂载到原型上
Car.prototype.drive = function() {
  return `Driving a ${this.color} ${this.brand}`; // 返回驾驶描述。
};

// 使用 new 关键字创建实例
const myCar = new Car('Tesla', 'white'); 
console.log(myCar.drive()); // 输出: Driving a white Tesla
console.log(myCar instanceof Car); // 输出: true，验证类型
```

# 模块

主要使用 `export` 和 `import` 这两个关键字。

## 语法格式

### `export` 语法格式

`export` 语句用于从模块中导出函数、对象、变量或类型，供其他模块通过 `import` 使用。导出的模块始终处于严格模式。

```javascript
// ========== 命名导出（Named Exports）==========
// 每个模块可以有多个命名导出

// 方式一：声明时直接导出
export let name1 = value1;          // 导出变量（使用 var、let、const 均可）
export const name2 = value2;        // 导出常量
export function funcName() { ... }  // 导出函数
export class ClassName { ... }      // 导出类

// 方式二：统一导出（先声明，后导出）
const myVar = 42;
function myFunc() { ... }
export { myVar, myFunc };           // 导出已声明的绑定

// 方式三：重命名导出
export { myVar as newName };        // 将 myVar 以 newName 的名称导出

// ========== 默认导出（Default Export）==========
// 每个模块只能有一个默认导出

export default expression;          // 导出任意表达式
export default function() { ... }   // 导出匿名函数
export default function name() { ... } // 导出具名函数
export default class { ... }        // 导出匿名类

// ========== 重导出（Re-exporting）==========
// 将其他模块的导出转发给当前模块

export * from "module-name";        // 导出目标模块的所有命名导出
export { name1, name2 } from "module-name"; // 选择性转发
export { name1 as newName } from "module-name"; // 重命名后转发
```

> **重要说明**
>
> - 命名导出在导入时必须使用相同的名称（除非使用 `as` 重命名）。
> - 默认导出在导入时可以使用任意名称。
> - `export * from "..."` **不会**转发目标模块的默认导出，需额外处理。

### `import` 语法格式

`import` 语句用于导入由其他模块导出的只读实时绑定（live bindings）。导入的绑定是只读的，不能被重新赋值。

```javascript
// ========== 导入命名导出 ==========

import { name1 } from "module-name";        // 导入单个命名导出
import { name1, name2 } from "module-name"; // 导入多个命名导出
import { name1 as alias } from "module-name"; // 重命名导入

// ========== 导入默认导出 ==========

import defaultExport from "module-name";    // 导入默认导出
// 注：defaultExport 可以是任意合法标识符

// ========== 命名空间导入 ==========

import * as namespace from "module-name";   // 将所有命名导出作为一个对象导入
// 使用时：namespace.name1、namespace.name2

// ========== 仅副作用导入 ==========

import "module-name";                       // 仅执行模块代码，不导入任何绑定

// ========== 混合导入 ==========

import defaultExport, { name1, name2 } from "module-name"; // 默认导出 + 命名导出
import defaultExport, * as namespace from "module-name";   // 默认导出 + 命名空间
```

### ts 专属扩展语法

TypeScript 完全支持上述所有 ES Module 语法，并在此基础上增加了类型相关的扩展。

#### 导出类型

```typescript
// TypeScript 中可以使用 export 修饰符导出类型声明

export type SomeType = string | number;           // 导出类型别名
export interface SomeInterface { name: string; }  // 导出接口
export enum Color { Red, Green, Blue }           // 导出枚举

// 也可以在统一导出中混合值与类型
export { f, SomeType, SomeInterface };
```

#### 类型专用导入与导出

TypeScript 3.8 引入了 `import type` 和 `export type` 语法，用于仅导入/导出类型（不包含运行时值）。这些导入/导出在编译后会被完全擦除，不会出现在输出的 JavaScript 中。

```typescript
// ========== 类型专用导入 ==========

import type { SomeType } from "./module.js";      // 仅导入类型
import type { SomeInterface } from "./module.js";

// 混合导入值与类型（使用 type 关键字标记类型）
import { f, type SomeInterface } from "./module.js";
// f 是值，SomeInterface 是类型

// ⚠️ 错误：不能同时导入默认和命名绑定
import type fs, { BigIntOptions } from "fs";      // ❌ 错误

// ✅ 正确：将默认导入作为命名绑定
import type { default as fs, BigIntOptions } from "fs";

// ========== 类型专用导出 ==========

export type { SomeType };                         // 仅导出类型
export type { AnInterface } from "./foo";         // 转发导出类型

// ⚠️ 注意：使用 import type 导入的类不能用作值（如不能 extends）
import type { Component } from "react";
class Button extends Component { }                // ❌ 错误：Component 仅作为类型使用
```

#### `import()` 类型

TypeScript 提供了一种类似动态导入的语法，用于在类型位置引用其他模块的类型，无需编写独立的 `import` 声明（内联导入类型）。

```typescript
// 在类型注解中直接导入类型
type Options = import("fs").WriteFileOptions;     // 导入 fs 模块中的类型
type WriteFn = typeof import("fs").writeFile;     // 导入值的类型

// 在 JSDoc 注释中特别有用
/** @type {import("webpack").Configuration} */
module.exports = { /* ... */ };
```

#### 传统 CommonJS 互操作

对于使用 CommonJS 风格导出的模块，TypeScript 提供了专用的导入语法。

```typescript
// 在 .d.ts 声明文件中
export = Greeter;                                 // 导出整个模块

// 对应的导入方式
import greeter = require("greeter");              // 使用 import = require() 导入
```

### 动态导入

除了静态 `import` 声明，JavaScript 还支持动态 `import()` 函数，用于按需加载模块。

```javascript
// 动态导入返回一个 Promise
import("./module.js")
    .then(module => {
        module.someFunction();                    // 使用模块的导出
    })
    .catch(err => {
        console.error("加载失败", err);
    });

// 结合 async/await 使用
const module = await import("./module.js");
```

## 语法成分详解

### `export`

| 语法成分                                            | 作用                               | 数据类型要求                              | 可选写法                               |
| :-------------------------------------------------- | :--------------------------------- | :---------------------------------------- | :------------------------------------- |
| **命名导出列表**（`{ name1, name2 }`）              | 导出已声明的变量、函数、类或类型   | 任意 JavaScript 值或 TypeScript 类型      | 可配合 `as` 重命名                     |
| **声明时导出**（`export let/const/function/class`） | 在声明的同时导出                   | 任意 JavaScript 值                        | 可省略初始化（`let` 可先声明后赋值）   |
| **默认导出**（`export default`）                    | 导出模块的默认值，每个模块仅有一个 | 任意表达式（值、函数、类等）              | 可导出匿名函数/类，也可导出具名函数/类 |
| **重导出全部**（`export * from "..."`）             | 转发目标模块的所有命名导出         | 目标模块的导出                            | 不包含默认导出                         |
| **重导出部分**（`export { ... } from "..."`）       | 选择性转发目标模块的导出           | 目标模块的指定导出                        | 可配合 `as` 重命名                     |
| **类型专用导出**（`export type`）【TypeScript】     | 仅导出类型，编译后完全擦除         | TypeScript 类型（接口、类型别名、枚举等） | 可配合 `from` 转发其他模块的类型       |

### `import`

| 语法成分                                        | 作用                         | 数据类型要求           | 可选写法                                   |
| :---------------------------------------------- | :--------------------------- | :--------------------- | :----------------------------------------- |
| **命名导入**（`{ name1, name2 }`）              | 导入目标模块的指定命名导出   | 与目标模块导出类型一致 | 可配合 `as` 重命名                         |
| **默认导入**（`defaultExport`）                 | 导入目标模块的默认导出       | 与默认导出类型一致     | 可使用任意合法的 JavaScript 标识符作为名称 |
| **命名空间导入**（`* as namespace`）            | 将所有命名导出聚合为一个对象 | 目标模块的所有命名导出 | 对象属性为各导出的名称                     |
| **仅副作用导入**（`import "..."`）              | 执行模块代码，不导入任何绑定 | 无                     | 无                                         |
| **混合导入**                                    | 同时导入默认导出和命名导出   | 默认导出 + 命名导出    | 默认导出必须在命名导出之前                 |
| **类型专用导入**（`import type`）【TypeScript】 | 仅导入类型，编译后完全擦除   | TypeScript 类型        | 可配合 `type` 关键字在混合导入中标记类型   |
| **动态导入**（`import()`）                      | 运行时按需异步加载模块       | 返回 `Promise<module>` | 可用于条件加载、代码分割                   |

## 配套语法与行为影响

### 循环与模块导入的配套行为

| 配套语法          | 适用场景                           | 行为影响                     |
| :---------------- | :--------------------------------- | :--------------------------- |
| **`break`**       | 在循环中配合模块加载逻辑           | 跳出循环，不影响已完成的导入 |
| **`continue`**    | 在循环中配合模块加载逻辑           | 跳过当前迭代，继续下一次循环 |
| **`try...catch`** | 配合动态 `import()` 捕获加载失败   | 捕获模块加载或执行时的错误   |
| **`await`**       | 配合动态 `import()` 或顶层 `await` | 等待模块加载完成后再继续执行 |

> **说明**：`export` 和 `import` 是声明式语句，不直接与 `break`、`continue` 等循环控制语句配合。上述表格主要针对动态 `import()` 在循环或异步流程中的使用场景。

### 模块导入导出的变体与修饰符

| 变体/修饰符              | 适用关键字         | 行为影响                                  |
| :----------------------- | :----------------- | :---------------------------------------- |
| **`as` 重命名**          | `export`、`import` | 改变导出或导入时的标识名称                |
| **`default`**            | `export`、`import` | 标记模块的默认导出/导入，每个模块仅有一个 |
| **`*`（通配符）**        | `import`、`export` | 导入/导出模块的所有命名导出               |
| **`type`**（TypeScript） | `import`、`export` | 标记导入/导出为纯类型，编译后擦除         |
| **`from`**               | `import`、`export` | 指定模块的来源路径                        |
| **`await`**（顶层）      | `import`           | 允许在模块顶层等待动态导入的结果          |
| **`with`**（导入属性）   | `import`、`export` | 为模块加载提供额外指令（如模块类型）      |

## 四、代码示例

### JS 中的命名导出与导入

```javascript
// ---------- math.js ----------
export const PI = 3.14159;
export function add(x, y) { return x + y; }
export function sub(x, y) { return x - y; }

// ---------- main.js ----------
import { PI, add, sub } from "./math.js";
console.log(add(PI, 2)); // 5.14159

// 重命名导入
import { add as plus } from "./math.js";
console.log(plus(1, 2)); // 3

// 命名空间导入
import * as math from "./math.js";
console.log(math.sub(5, 3)); // 2
```

### JS 中的默认导出与导入

```javascript
// ---------- greet.js ----------
export default function(name) {
    return `你好，${name}！`;
}

// 也可以先声明再默认导出
function sayHello(name) { return `Hello, ${name}!`; }
export default sayHello;

// ---------- main.js ----------
// 默认导入可以使用任意名称
import greet from "./greet.js";
console.log(greet("小明")); // 你好，小明！
```

### TS 中的类型导出与导入

```typescript
// ---------- types.ts ----------
export interface User {
    id: number;
    name: string;
    email?: string;
}

export type UserRole = "admin" | "user" | "guest";

export function createUser(name: string): User {
    return { id: Date.now(), name };
}

// ---------- main.ts ----------
// 混合导入：值和类型可以一起导入
import { createUser, type User, type UserRole } from "./types.js";

const admin: UserRole = "admin";
const user: User = createUser("张三");
```

### TS 中的类型专用导入与导出

```typescript
// ---------- shapes.ts ----------
export interface Circle {
    radius: number;
    area(): number;
}

export class Square {
    constructor(public side: number) {}
    area(): number { return this.side ** 2; }
}

// ---------- index.ts ----------
// 仅导出类型，不导出实现
export type { Circle } from "./shapes.js";

// 值和类型分开导入
import { Square } from "./shapes.js";        // 导入值（类）
import type { Circle } from "./shapes.js";   // 仅导入类型

const square = new Square(5);                // ✅ Square 是值，可以实例化
// const circle: Circle = { radius: 10, area: () => 314 }; // ✅ Circle 是类型
```

### 动态导入

```javascript
// 按需加载模块
async function loadModule() {
    try {
        const module = await import("./heavy-module.js");
        module.doSomething();
    } catch (error) {
        console.error("模块加载失败", error);
    }
}

// 条件加载
if (condition) {
    const { feature } = await import("./feature-a.js");
    feature.run();
} else {
    const { feature } = await import("./feature-b.js");
    feature.run();
}
```

### 重导出（模块聚合）

```javascript
// ---------- shapes/index.js ----------
// 聚合多个子模块的导出
export { Circle } from "./circle.js";
export { Square } from "./square.js";
export { Triangle } from "./triangle.js";

// ---------- main.js ----------
// 只需导入一个入口
import { Circle, Square, Triangle } from "./shapes/index.js";
```

> `export * from "..."` 不会转发默认导出。如需转发默认导出，需显式处理。
>
> ```javascript
> import mod from "mod";
> export default mod;
> ```
