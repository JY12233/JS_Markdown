# 逻辑运算

JavaScript 中的逻辑运算主要用于布尔判断和流程控制。它包含三大类运算符：逻辑与（`&&`）、逻辑或（`||`）、逻辑非（`!`），以及较新的空值合并运算符（`??`）。

需要特别注意的是，JS 中的逻辑运算符并不总是返回布尔值（`true` 或 `false`），而是会返回**实际参与运算的操作数**的值。

## 逻辑与（`&&`）

- 作用

  只有当所有条件都为真时，结果才为真。

- 返回值规则

  - 如果第一个操作数为假值（falsy），则直接返回**第一个操作数**（短路特性，不会继续计算后面的值）。
  - 如果第一个操作数为真值（truthy），则返回**第二个操作数**。

- 示例

  ```javascript
  console.log(true && 'hello');  // 输出: 'hello'
  console.log(false && 'hello'); // 输出: false
  console.log('' && 'hello');    // 输出: '' (空字符串是假值)
  ```

## 逻辑或（`||`）

- 作用

  只要有一个条件为真，结果就为真。

- 返回值规则

  - 如果第一个操作数为真值，则直接返回**第一个操作数**（短路特性）。
  - 如果第一个操作数为假值，则返回**第二个操作数**。

- 示例

  ```javascript
  console.log(true || 'hello');  // 输出: true
  console.log(false || 'hello'); // 输出: 'hello'
  console.log('' || 'default');  // 输出: 'default'
  ```

## 逻辑非（`!`）

- 作用

  将操作数转换为布尔值，然后取反。

- 返回值规则

  永远返回布尔值（`true` 或 `false`）。

- 示例

  ```javascript
  console.log(!true);   // 输出: false
  console.log(!'hello'); // 输出: false (非空字符串是真值，取反为 false)
  console.log(!0);      // 输出: true (0 是假值，取反为 true)
  ```

- 双重非运算符（`!!`）

  常用于将任意值强制转换为对应的布尔值。例如 `!!'hello'` 为 `true`，`!!0` 为 `false`。

## 空值合并运算符（`??`）

- 作用

  这是 ES2020 引入的新运算符。它只在左侧为 `null` 或 `undefined` 时，才返回右侧的值。

- 与 `||` 的区别

  `||` 会把所有假值（如 `0`、`''`、`false`）都当作“不存在”而返回右侧值，而 `??` 只认 `null` 和 `undefined`。

- 示例

  ```javascript
  console.log(0 || 'default');  // 输出: 'default' (0 是假值)
  console.log(0 ?? 'default');  // 输出: 0 (0 不是 null/undefined，保留原值)
  
  console.log(null ?? 'default'); // 输出: 'default'
  ```

## 真值（Truthy）与假值（Falsy）

理解逻辑运算的关键在于知道哪些值在 JS 中被视为“假”。

- 常见的假值（Falsy）

  `false`、`0`、`-0`、`0n`（BigInt）、`""`（空字符串）、`null`、`undefined`、`NaN`。

- 真值（Truthy）

  除了上述假值以外的所有值，包括空数组 `[]`、空对象 `{}`、非空字符串 `"0"` 等。

## 总结对比表

| 运算符 | 名称     | 核心逻辑 | 返回值特点                               |
| ------ | -------- | -------- | ---------------------------------------- |
| `&&`   | 逻辑与   | 全真才真 | 返回第一个假值，或最后一个真值。         |
| `||`   | 逻辑或   | 一真即真 | 返回第一个真值，或最后一个假值。         |
| `!`    | 逻辑非   | 真假反转 | 永远返回布尔值（`true`/`false`）。       |
| `??`   | 空值合并 | 仅判空   | 左侧为 `null`/`undefined` 时返回右侧值。 |

# ? 的用法

在 JavaScript 中，问号 `?` 主要有三种核心用法，分别是三元运算符、可选链操作符以及空值合并运算符。

## 三元运算符

这是 `?` 最基础的用法，用于简化 `if...else` 语句。它接受三个操作数：条件、条件为真时的返回值、条件为假时的返回值。

- 语法格式

  `条件 ? 表达式1 : 表达式2`

- 代码示例

  ```javascript
  const age = 20;
  // 如果 age >= 18，返回 '成年人'，否则返回 '未成年人'
  const status = age >= 18 ? '成年人' : '未成年人';
  console.log(status); // 输出: '成年人'
  ```

## 可选链操作符

这是 ES2020 引入的语法，用于安全地访问深层嵌套的对象属性。如果链条中的某个引用是 `null` 或 `undefined`，表达式会短路并返回 `undefined`，而不会抛出错误。

- 语法格式

  `对象?.属性` 或 `对象?.[表达式]` 或 `函数?.()`

- 代码示例

  ```javascript
  const user = {
      name: '张三',
      address: {
          city: '北京'
      }
  };
  
  // 安全访问深层属性
  console.log(user.address?.city); // 输出: '北京'
  console.log(user.contact?.phone); // 输出: undefined (不会报错)
  
  // 安全调用方法
  const someFunc = null;
  console.log(someFunc?.()); // 输出: undefined (不会报错)
  ```

## 空值合并运算符

`??`，虽然它由两个问号组成，但也是 `?` 的重要用法。它只在左侧为 `null` 或 `undefined` 时，才返回右侧的值。这与逻辑或（`||`）不同，`||` 会把 `0`、`''`、`false` 等假值也当作“不存在”。

- 语法格式

  `左侧值 ?? 右侧默认值`

- 代码示例

  ```javascript
  console.log(0 ?? '默认值'); // 输出: 0 (0 不是 null/undefined，保留原值)
  console.log('' ?? '默认值'); // 输出: '' (空字符串保留原值)
  console.log(null ?? '默认值'); // 输出: '默认值'
  ```

## 三种用法对比总结

| 符号  | 名称       | 核心作用          | 典型场景                             |
| ----- | ---------- | ----------------- | ------------------------------------ |
| `? :` | 三元运算符 | 简化条件判断      | 简单的 if...else 赋值                |
| `?.`  | 可选链     | 安全访问属性/方法 | 访问深层嵌套对象，避免报错           |
| `??`  | 空值合并   | 提供默认值        | 仅当值为 null/undefined 时使用默认值 |

# 解构赋值

## 定义与本质

解构赋值（Destructuring Assignment）是 ES6 引入的一种语法特性，允许从数组或对象中提取值，并赋值给独立的变量。其本质是一种“**模式匹配式提取**”，通过在赋值运算符（`=`）左侧定义一个与右侧数据结构相匹配的模式（如数组模式或对象模式），自动完成值的读取与变量的绑定。解构赋值不会创建新的对象或数组，仅仅是读取和重绑定变量。

## 核心作用

- 简化代码

  大幅减少从复杂数据结构中提取数据的样板代码，使代码更加紧凑。

- 提升可读性

  通过声明式的模式匹配，使代码意图更加清晰直观。

- 安全提取

  支持设置默认值，有效防止因数据缺失导致的运行时错误。

- 优化函数参数

  在函数定义时直接解构参数，使函数签名更具描述性。

## 分类与使用规则

解构赋值主要分为数组解构和对象解构两大类，两者的匹配机制截然不同。

### 数组解构

数组解构（Array Destructuring）基于**位置（索引）**进行匹配。左侧模式中的变量会按照顺序，接收右侧数组中对应位置的元素。

#### 基础语法

```javascript
const [变量1, 变量2, ...变量N] = 数组;
// 变量1：接收数组索引为 0 的元素
// 变量2：接收数组索引为 1 的元素
// ...变量N：剩余参数，收集剩余的所有元素为一个新数组
```

#### 核心特性

- 跳过元素

  在模式中留空（仅保留逗号），可以忽略不需要的元素。例如 `const [a, , c] = [1, 2, 3];`。

- 默认值

  当数组中对应位置的值为 `undefined` 或不存在时，使用默认值。例如 `const [a = 10] = [];`。

- 剩余元素

  使用 `...rest` 语法收集数组中剩余的元素，必须放在模式的最后。

- 嵌套解构

  支持对嵌套数组进行多层解构，只要左侧模式与右侧结构匹配即可。

### 对象解构

对象解构（Object Destructuring）基于**属性名（键名）**进行匹配，与书写顺序无关。左侧模式中的变量名必须与右侧对象的属性名一致，才能成功提取值。

#### 基础语法

```javascript
const { 属性1, 属性2: 新变量名, ...rest } = 对象;
// 属性1：提取同名属性，并赋值给同名变量
// 属性2: 新变量名：提取属性2的值，但赋值给名为“新变量名”的变量
// ...rest：剩余属性，收集剩余的可枚举属性为一个新对象
```

#### 核心特性

- 重命名

  使用 `属性名: 新变量名` 的语法，将提取的值赋给不同名的变量。

- 默认值

  当对象中不存在该属性或属性值为 `undefined` 时，使用默认值。注意：属性值为 `null` 时不会触发默认值。

- 嵌套解构

  支持逐层提取深层属性。例如 `const { info: { id } } = obj;`。若中间层属性可能为 `undefined`，需设置默认空对象以防止报错。

## 常见应用场景

- 变量交换：无需临时变量即可交换两个变量的值。

  ```javascript
  let a = 1, b = 2;
  [a, b] = [b, a];
  ```

  > `b` 的后面一定要添加 `;`，不然 JavaScript 会把它误解为是属性的访问。因为数组有 `array[index]` 访问数据的方法，所以 JavaScript 就会理解成 `let b = ((2)[(a, b)] = [b, a])`。

- 函数参数解构：在函数定义时直接解构传入的对象或数组，使参数结构一目了然。

  ```javascript
  function createUser({ name, age, role = 'user' }) {
      // 直接使用 name, age, role
  }
  ```

- 配置对象初始化：从配置对象中提取参数并设置默认值，增强函数的容错性。

  ```javascript
  function init({ timeout = 5000, retries = 3 } = {}) {
      // 即使不传参也不会报错
  }
  ```

- 循环中的解构：在 `for...of` 循环中直接解构数组元素，简化遍历逻辑。

  ```javascript
  for (const { id, name } of users) {
      console.log(id, name);
  }
  ```

- 多级对象解构

  ```js
  let {
      name,
      family: { mother, father, son },
  } = {
      name: "佩奇一家",
      family: {
          mother: "猪妈妈",
          father: "猪爸爸",
          son: "乔治",
      },
  };
  ```


## 注意事项

- 区分括号

  数组解构使用方括号 `[]`，对象解构使用花括号 `{}`，两者不可混用。

- 避免过度嵌套

  过深的解构模式会降低代码可读性，必要时可分步解构。

- 注意 `null` 和 `undefined`

  不能对 `null` 或 `undefined` 进行解构，否则会抛出 `TypeError`。在解构可能为空的变量时，应先进行判空或设置默认值。

- 赋值模式需加括号

  在不使用 `let/const/var` 声明的赋值模式中，如果左侧是对象解构，必须用圆括号包裹，以避免被解析为代码块。例如 `({ a, b } = obj);`。

# 异常处理

## 定义与本质

异常处理（Exception Handling）是 JavaScript 中用于捕获、处理程序执行过程中产生的错误，从而避免程序意外崩溃的机制。当 JavaScript 引擎执行代码时，可能会遇到语法错误、运行时错误（如引用未定义的变量）或不可预知的因素。异常处理机制允许程序在遇到这些问题时，能够优雅地恢复、提供有用的错误信息或进行必要的资源清理，而不是直接终止运行。

## 语法结构

`try...catch...finally` 语句是 JavaScript 处理同步代码异常的基础结构。

- try 块

  包裹可能抛出异常的代码。如果 `try` 块内的代码在执行过程中发生错误，程序会立即停止执行剩余代码，并跳转到 `catch` 块。

- catch 块

  定义当 `try` 块发生错误时执行的错误处理逻辑。`catch` 块会接收一个错误对象（通常命名为 `error` 或 `e`），该对象包含了错误的详细信息（如 `message` 和 `stack`）。如果 `try` 块没有抛出异常，`catch` 块将被跳过。

- finally 块

  定义无论是否抛出异常，最终都必须执行的代码。它通常用于执行清理工作（如关闭文件、释放网络连接、重置状态等）。即使 `try` 或 `catch` 块中包含 `return` 语句，`finally` 块依然会在函数返回前执行。

## 主动抛出异常

`throw` 语句允许开发者主动抛出一个自定义的异常。当程序检测到不满足预期的参数或状态时，可以使用 `throw` 中断当前执行流，并将控制权转移给最近的 `catch` 块。

- 抛出内容

  `throw` 后面可以跟随任意类型的值，包括字符串、数字、布尔值或对象。

- 最佳实践

  通常建议抛出 `Error` 对象或其子类（如 `TypeError`，`RangeError`），因为 `Error` 对象包含了错误名称、消息以及堆栈跟踪（Stack Trace）信息，便于后续调试和日志记录。

## 异步代码的异常处理

在处理异步操作时，传统的 `try...catch` 无法直接捕获异步回调中的错误，需要使用特定的异步异常处理机制。

- Promise 链式调用

  使用 `.catch()` 方法捕获 Promise 链中任何环节抛出的异常。

- async/await 语法

  `async/await` 使得异步代码看起来像同步代码。在 `async` 函数内部，可以直接使用 `try...catch` 语句来捕获 `await` 表达式可能产生的异常。这是目前处理异步错误最主流且最清晰的方式。

## 错误对象

JavaScript 提供了一系列标准的错误构造函数，用于生成特定类型的错误对象。

- `Error`：通用的错误基类。
- `SyntaxError`：语法解析错误。
- `ReferenceError`：引用未声明的变量时抛出。
- `TypeError`：变量或参数不是预期类型时抛出（如对非函数进行调用）。
- `RangeError`：数值超出有效范围时抛出（如创建超长数组）。

## 代码示例

```javascript
// 1. 基础异常处理结构
try {
  // 模拟一个可能出错的代码块
  const result = riskyOperation();
  console.log(result);
} catch (error) {
  // 捕获并处理错误
  console.error('发生错误:', error.message);
} finally {
  // 无论是否出错，都会执行清理工作
  console.log('操作结束，执行清理...');
}

// 2. 主动抛出异常
function divide(a, b) {
  if (b === 0) {
    throw new RangeError('除数不能为 0');
  }
  return a / b;
}

// 3. async/await 异步异常处理
async function fetchData() {
  try {
    const response = await fetch('/api/data');
    const data = await response.json();
    return data;
  } catch (error) {
    console.error('数据获取失败:', error);
  }
}
```

## 注意事项

- 保持 try 块作用域最小化

  只包裹真正可能抛出异常的代码，避免过度使用 `try...catch` 导致性能下降或掩盖其他逻辑错误。

- 避免空的 catch 块

  空的 `catch` 块会静默吞掉错误，导致问题难以排查。至少应该记录错误日志。

- 使用 `console.error()`

  在调试或记录错误时，使用 `console.error()` 而非 `console.log()`，以便在控制台中以错误样式高亮显示。

- 不要滥用异常控制流

  异常处理应仅用于处理真正的异常情况，不应作为常规的业务逻辑控制手段（如用异常来处理正常的分支判断），因为这会严重影响代码的可读性和性能。
